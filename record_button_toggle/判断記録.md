# 判断記録

`plugin_idea.md`の元メモ(「追加・編集・コピーボタン非表示プラグイン」の項)は「サイドバーと同様で
追加編集コピーを制御する。」の1行のみで、実装時に暫定判断が必要だった事項を記録する。作業は止めずに
進めた。基本方針は`sidebar_toggle/判断記録.md`・`group_field_toggle/判断記録.md`を踏襲している。

## 1. 一覧・グラフ画面(レコード文脈が無い画面)では「常に」ルードのみを適用する設計にした

- **問題**: 追加ボタンは一覧・グラフ画面にも表示されるが、これらの画面には「今表示している1件の
  レコード」という概念が無い。元メモには条件評価の対象画面についての言及が無かった。
- **選んだ暫定対応**: `rule-matcher.js`の`findMatchingRule()`に`record`として`null`を渡した場合、
  `mode: 'MATCH'`(条件付き)のルールは一致させず、`mode: 'ALWAYS'`のルールのみを対象にする設計に
  した。存在しないレコードに対して条件を「たまたま真/偽」と評価してしまう(例:
  `IS_EMPTY`が常に真になってしまう)方が誤動作のリスクが高いと判断し、安全側に倒した。
- **要ユーザー確認**: 一覧・グラフ画面でも何らかの形で条件評価が必要な場合(例:
  検索条件・絞り込み条件を使う等)は設計の再検討が必要。

## 2. コピー(再利用)ボタンはPC専用とした

- **問題**: `kintone.app.record.showDuplicateRecordButton()`のモバイル版関数名が、参照した
  cybozu developer networkのページに明記されていなかった(PC向け関数名のみ記載)。
- **選んだ暫定対応**: モバイル版の存在が確認できなかったため、コピーボタンの制御はPC専用とした
  (`js/mobile.js`では対象ボタンから除外)。
- **要ユーザー確認**: モバイル版のコピーボタン制御が必要な場合、`kintone_doc` MCPが利用可能に
  なった時点で正式なAPI名を確認し直す必要がある。

## 3. 詳細画面での値変更時の再評価は実装しなかった

- **問題**: `sidebar_toggle`/`group_field_toggle`は編集画面での値変更時に再評価する仕組みを持つが、
  本プラグインが制御するボタン(追加・編集・コピー)はいずれもレコード詳細画面(表示専用、
  フィールド編集不可)に表示されるボタンであり、詳細画面には`change`系イベントが存在しない。
- **選んだ暫定対応**: 再評価の仕組み自体を実装しなかった(表示時の一度きりの適用で十分)。
- **要ユーザー確認**: 対応不要(画面の仕様上、値変更が起こらないため)。

## 4. 条件エンジン・ルール優先順位・「常に」の解釈はsidebar_toggle/group_field_toggleを踏襲した

- `sidebar_toggle/判断記録.md`の1〜3番と同じ判断を踏襲している。詳細はそちらを参照。

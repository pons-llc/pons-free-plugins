# レコード指摘改善プラグイン

## 機能概要

- レコード詳細画面で、**フィールドごと・テーブルの行ごとに修正指摘(コメント)を下書きし、まとめて登録**できる(v2)。
  - 「指摘モード」をONにすると、各フィールドの右上とテーブルの各行の右側に「＋」が出る。押すと画面右下の
    **下書きパネル**に入力欄が追加される(同じ対象を再度押しても増えず、その入力欄にフォーカスする。下書き済みの対象は「✎」表示)。
  - 指摘したい箇所をすべて書いてから「まとめて登録(n件)」を押すと、1回の保存で全件を登録する(指摘日時・指摘者は全件同じ)。
    内容が空の下書きは登録対象から外し、1件も内容が無ければエラーにする。「すべて破棄」で下書きを捨てられる。
  - 1件ずつ即保存する登録口は設けない(バッジのダイアログからも「下書きに追加」するだけ)。v1の「1フィールドずつ登録」を
    利用者の要望で置き換えた。
  - 未保存の下書きがある状態でページを離れようとすると、ブラウザの離脱確認を出す。別のレコードへ移動したときは下書きを捨てる。
- 指摘はレコード内のサブテーブル(指摘履歴)に1指摘=1行で保存する。サブテーブルは**プラグイン設定画面の
  保存だけで自動作成**される(`approval_history`と同じ`POST /k/v1/preview/app/form/fields.json` →
  `POST /k/v1/preview/app/deploy.json`の仕組み)。手動でのフィールド作成は不要。
- 未解決の指摘があるフィールド・行には**赤いバツマーク(✕+件数)**が付き、フィールドは赤枠で囲まれる。
  マークにマウスを乗せると未解決の指摘内容がツールチップで表示され、クリックすると指摘の詳細ダイアログが開く。
  ダイアログで**解決内容を入力して「解決済みにする」**を押すと、対応者・解決日時とともに記録される(解決は1件ずつ)。
- 指摘がすべて解決済みのフィールド・行には**緑のチェックマーク(✓)**が付く。
- レコード上部の「指摘履歴」ボタンから、レコード内のすべての指摘(解決済みを含む)を時系列で閲覧できる。
  サブテーブル自体も詳細画面にそのまま表示されるため、そこからも履歴を確認できる。
- 狙い: 審査・決裁・校閲などで「どの項目の・何が・誰に指摘され・どう直したか」を、レコードそのものの
  一部として残す。コメント欄(レコード単位)では項目との対応が曖昧になる問題を解消する。

## テーブルの行単位の指摘(v2)

- 指摘できるフィールドとしてテーブルを選ぶと、テーブル全体(テーブルの右上のバッジ)に加えて、**各行**にも指摘できる。
- 行は`rr_target_row_id`(対象行ID)にkintoneのテーブル行の`id`を保存して紐付ける。行番号ではなく行IDなので、
  行の並べ替え・途中の行の削除があっても指摘は正しい行に付いたまま。表示時に現在の並び順で「テーブル名 n行目」を振り直す。
  `rr_target_label`には指摘時点の「テーブル名 n行目」を保存する(サブテーブル・CSVで読めるように)。
- 対象の行が削除された指摘は、テーブル全体のバッジに寄せて表示する(未解決の指摘が画面から消えないように)。
  表示名は「(保存時のラベル)(削除された行)」。
- 行の要素: `getFieldElement(テーブル)`は詳細画面で`<table>`を返し、`tbody`直下の`<tr>`がレコードの行の並び順と
  一致する(実機で確認済み)。**読み取って位置を測るだけで、DOMは変更しない**。`<tr>`の数が行数と一致しない場合
  (kintoneの内部構造の変更など)は行のバッジを出さず、行の指摘はテーブル全体のバッジに寄せる(安全側)。
- 下書きパネルの行の項目には、行の値を先頭から最大3つ要約して表示し、どの行かを見分けやすくする。

## v1からの更新

- v1で作成した指摘履歴テーブルには「対象行ID」列が無い。設定画面を開くと「保存すると列を追加します」と表示し、
  保存時に**不足している列だけを既存テーブルに追加**してデプロイする(既存の列・データは変更しない)。
  - 既存テーブルへの内包フィールドの追加は、**フィールド追加API(POST)**にテーブルのコード・現在のラベルと追加する
    内包フィールドだけを指定して行う。フィールド設定変更API(PUT)に新しい内包フィールドを指定すると
    「指定されたフィールド(code: rr_target_row_id)が見つかりません」になる(いずれも実機で確認済み)。
  - 「v1からある項目はすべて型が一致し、欠けているのはv2で追加した項目だけ」のテーブルのみ更新対象にする。
    それ以外は従来どおり別コードで新規作成する。
- 設定を再保存するまでは、行単位の指摘は使えず(行の「＋」を出さない)、フィールド単位の指摘・解決はそのまま使える。
- 連番付きのコード(`review_comment_table_2`等)で作成済みの場合、再保存で別のテーブルを増やさないよう、
  保存済みのテーブルコードを最優先で照合する(v1では既定コードしか照合しておらず、再保存のたびに連番テーブルが
  増える可能性があったのをv2で修正)。

## サブテーブルの構成(固定・1指摘=1行)

サブテーブルのフィールドコードは`review_comment_table`(ラベル: 指摘履歴)を既定とする。

| 項目 | フィールドコード | 型 | 内容 |
| :-- | :-- | :-- | :-- |
| 対象フィールドコード | `rr_target_code` | 文字列(1行) | 指摘対象フィールドのフィールドコード(バッジ表示の紐付けキー) |
| 対象項目 | `rr_target_label` | 文字列(1行) | 指摘時点の対象フィールド名(行の指摘は「テーブル名 n行目」) |
| 対象行ID | `rr_target_row_id` | 文字列(1行) | テーブルの行単位の指摘の場合、対象行の`id`(v2で追加。フィールド単位の指摘は空) |
| 指摘日時 | `rr_pointed_at` | 日時 | 指摘登録時のブラウザ時刻 |
| 指摘者 | `rr_pointed_by` | ユーザー選択 | 指摘を登録したログインユーザー |
| 指摘内容 | `rr_comment` | 文字列(複数行) | 指摘内容 |
| 解決状況 | `rr_status` | ドロップダウン | `未解決` / `解決済み`(初期値`未解決`) |
| 解決内容 | `rr_resolution` | 文字列(複数行) | 解決時に入力した対応内容 |
| 対応者 | `rr_resolved_by` | ユーザー選択 | 「解決済みにする」を押したログインユーザー |
| 解決日時 | `rr_resolved_at` | 日時 | 解決登録時のブラウザ時刻 |

- 既定コードが既存の別フィールドと衝突する場合は、`approval_history`と同様に末尾へ連番(`_2`、`_3`…)を
  付けて新規作成する(既存フィールドの構造は書き換えない)。内包フィールドの型・ドロップダウンの選択肢
  (`未解決`/`解決済み`)をすべて満たすテーブルが既にあれば再利用する(冪等)。
- 日時はブラウザ時刻(`approval_history/idea.md`「実行日時について」と同じ制約)。

## 設定画面

- 指摘履歴テーブルの状態(作成済み/保存時に自動作成)を表示する。
- **指摘できるフィールド**をチェックボックスで選ぶ(既定はすべて)。候補はフォームレイアウト順で、
  次を除外する: ステータス・作業者・カテゴリー・レコード番号・作成者・作成日時・更新者・更新日時、
  グループ、指摘履歴テーブル自身。テーブル・関連レコード一覧は(PC詳細画面で要素が取得できるため)対象に含める。
  何も選ばずに保存した場合はエラーにする。
- 保存時、必要ならフィールド追加→デプロイ→デプロイ完了ポーリングを行い、成功したら
  フィールドコード一式と対象フィールドを`kintone.plugin.app.setConfig()`に保存する。

## 画面ごとの挙動

- **詳細画面(PC)**
  - `kintone.app.record.getHeaderMenuSpaceElement()`に「未解決の指摘 n件」表示・「指摘履歴」ボタン・
    「指摘モード」切替ボタンを置く。
  - 対象フィールドの要素は`kintone.app.record.getFieldElement()`で取得する。ドキュメント上
    「取得した要素の内部構造を変更すると…動作しなくなる可能性」があるため、**バッジは要素内に挿入せず**、
    `document.body`直下のオーバーレイ層に、要素の`getBoundingClientRect()`から計算した位置で絶対配置する
    (リサイズ・スクロール・定期的な再計算で追従)。赤枠はドキュメントで許可されている`style`変更で付ける。
  - 指摘モードON時は、すべての対象フィールド・テーブルの各行に「＋」ボタンを出し、指摘を下書きに追加できる
    (OFF時は指摘のある対象にだけバッジを出し、画面を散らかさない)。指摘モードのON/OFFは
    `localStorage`に記憶する(失敗しても動作に影響しない)。
  - 指摘のまとめて登録・解決は、最新レコードを`GET /k/v1/record.json`で取得し、変更行以外は`{id}`のみ
    (ドキュメント「行の並べ替えのみを行う場合は…idだけ」= 値保持)、変更行はフル値で
    `PUT /k/v1/record.json`する。`revision`を指定し、他ユーザーと競合した場合はエラー表示して再読み込みを促す。
    成功後は画面を再読み込みして表示を更新する。
- **追加・編集画面/一覧のインライン編集**
  - 指摘履歴テーブルの全行の内包フィールドを`disabled`にする(SUBTABLE自体への`disabled`は効かないため
    `approval_history`と同じく行単位。`change.<テーブル>`でも再適用)。
  - **再利用(`event.reuse`)で追加画面を開いた場合は、指摘履歴テーブルを空にする**(コピー元の指摘を引き継がない)。
  - 編集画面では、メニュー上側に未解決の指摘一覧(項目名〈行は「n行目」〉・指摘内容・指摘者)を表示し、修正しながら確認できるようにする。
- **モバイル**
  - 追加・編集画面で指摘履歴テーブルを編集不可にする(再利用時のクリアも同様)。
  - 詳細画面では、ヘッダー下(`kintone.mobile.app.getHeaderSpaceElement()`)に未解決の指摘一覧を表示する
    (閲覧のみ。モバイルではテーブル等の要素が取得できないため、フィールド横のバッジは出さない)。

## エッジケース

- 指摘履歴テーブルが削除された・設定未保存 → 何もしない(画面は通常どおり)。
- 対象フィールドがフィールド権限で非表示(`getFieldElement()`がnull)・折りたたまれたグループ内(幅0) → バッジを出さない。
- 設定後に対象フィールドが削除された → そのフィールド宛の指摘は「指摘履歴」ダイアログでのみ閲覧可能。
- レコード編集権限がない利用者 → 登録時のPUTがエラーになり、エラーメッセージを表示する。
- 指摘内容・解決内容が空(空白のみ)の場合は登録しない。

## API実行数

- 詳細画面表示時: 0回(フィールド情報はJavaScript API`getFormFields()`/`getFormLayout()`で取得)。
- まとめて登録1回(件数によらず)・解決1回につき: 2回(GET record + PUT record)。

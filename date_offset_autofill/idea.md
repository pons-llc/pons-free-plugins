# 日付自動入力プラグイン(date_offset_autofill)

## 機能概要

kintoneのCALCフィールドで日付演算(`基準日 + 10`のような加減算)を行うと、結果は**文字列/日付として
固定された値**になり、レコード一覧の絞り込みで「今日」「今月」のような動的な条件を使えない
(CALCフィールドは絞り込み条件の対象にできるが、値そのものは保存時点で確定した固定値であり、
`基準日`が更新されない限り再計算されない)。

本プラグインは、レコード保存時(`submit`イベント)に、**基準となるDATE/DATETIMEフィールドの値**に
指定した値(日数または分数)をプラスマイナスして、**別のDATE/DATETIMEフィールド**へ実際の値として
書き込む。書き込み先は通常のDATE/DATETIMEフィールドのため、レコード一覧の絞り込みで「今日」
「今月」等の動的な条件をそのまま使える。

- 設定ルールを複数持てる(1つの基準フィールドに対して複数のルールを作ることも、複数の異なる
  基準フィールドに対してそれぞれ設定することもできる)。
- ルールごとに、基準フィールド・単位(日数/分数)・オフセット値の種類(固定値/フィールド参照)・
  オフセット値・出力先フィールドを持つ。

### 例(元メモのユースケース)

緊急度を選ぶラジオボタンに連動する計算フィールド(緊急度「高」なら10、「中」なら20、のような
数値を返すCALCフィールド)を用意しておき、本プラグインで「基準フィールド=申請日、単位=日数、
オフセット値=このCALCフィールドを参照、出力先=期限日」というルールを設定すると、保存のたびに
`期限日 = 申請日 + 緊急度に応じた日数`が自動入力される。`期限日`は通常のDATEフィールドなので、
一覧画面で「期限日が今日以前」のような動的な絞り込みがそのまま使える。

## オフセット値の指定方法(確定)

- **単位**: `DAYS`(日数)または`MINUTES`(分数)。kintoneのDATETIME(日時)フィールドは入力UI上
  分単位までしか扱えない(時刻入力欄に秒の指定が無い)ため、秒数ではなく分数を単位とする。
- **値の種類**:
  - `FIXED`(固定値): 設定画面で入力する固定の数値。正負・小数を許可する(例: `-5`で5日前、
    `0.5`で12時間後)。符号自体でプラス/マイナスを表現するため、別途「符号」の設定項目は
    設けない(値をそのまま基準日へ加算する)。
  - `FIELD`(フィールド参照): 数値(`NUMBER`)フィールド、または表示書式が「数値」
    (`format`が`NUMBER`または`NUMBER_DIGIT`)の計算(`CALC`)フィールドの値を、実行時に
    毎回読み取って使う。フィールドの値が数値として解釈できない(空文字列等)場合、そのルールは
    スキップする(基準日が無い場合と同じ扱い、詳細は「エッジケース」参照)。

## 基準フィールド・出力先フィールドの制約(確定)

- 基準フィールド・出力先フィールドは、どちらもDATE(日付)またはDATETIME(日時)型のフィールド
  から選択する。
- **基準フィールドと出力先フィールドは同じ型(DATE同士、またはDATETIME同士)でなければならない**
  (設定画面のバリデーションで強制する)。DATE→DATETIMEやDATETIME→DATEのような型をまたいだ
  変換は、時刻の扱いが曖昧になる(DATEには時刻情報が無い)ため対象外とした(スコープ限定)。
- **単位`MINUTES`は、基準フィールド・出力先フィールドが共にDATETIME型の場合のみ選択できる**。
  DATE型フィールドは日単位より細かい情報を持たないため、分単位の加減算は意味を持たない
  (設定画面のバリデーションで弾く)。単位`DAYS`はDATE・DATETIMEのどちらでも使える。
- 出力先フィールドはCALC(計算)フィールドにはできない(CALCフィールドはAPI/JavaScript APIから
  値の登録・更新ができない仕様のため、フィールド選択肢自体をDATE/DATETIME型に絞り込むことで
  自然に対象外になる)。

## 日付演算の実装方針(確定・実データに基づく実装)

kintoneドキュメントMCP「フィールド形式」で、DATE型の値は`"2012-01-11"`(タイムゾーンなしの暦日)、
DATETIME型の値は`"2012-01-11T11:30:00Z"`(UTC、ミリ秒なしのISO8601)であることを確認済み。

- **DATE型同士**: `Date.UTC(year, month - 1, day)`でUTCのタイムスタンプを組み立て、
  オフセット(ミリ秒換算)を加算し、結果を`getUTCFullYear()`/`getUTCMonth()`/`getUTCDate()`から
  `YYYY-MM-DD`へ整形する。**常にUTCの日付演算として扱う**(`age_grade_field_update`の
  `current-value-formatter.js`が「ローカルの`Date`で日付を切り出すとタイムゾーンでずれる」ことを
  教訓にしているのに対し、DATE型自体がタイムゾーンを持たない暦日である本プラグインでは、
  ローカルタイムゾーンを一切介在させずUTC演算に統一することで、DST(夏時間)の影響も受けない
  安全な実装にしている)。
- **DATETIME型同士**: `new Date(値)`でUTCの瞬間としてパースし(末尾`Z`付きの文字列は標準で
  UTCとして解釈される)、オフセット(ミリ秒換算、`MINUTES`単位なら`分数 * 60000`、`DAYS`単位なら
  `日数 * 86400000`)を加算し、`toISOString().replace(/\.\d{3}Z$/, 'Z')`でミリ秒なしのUTC
  ISO8601形式に整形する(`age_grade_field_update`の`formatDatetime`と同じ手法)。
- 基準フィールドの値が空(未入力)の場合、そのルールはスキップする(出力先フィールドを
  上書きしない)。
- オフセット値が数値として解決できない場合(固定値が不正、またはフィールド参照で参照先の値が
  空/非数値)、そのルールはスキップする(部分的な失敗で保存処理全体を止めない)。

## 発動タイミング・編集禁止の仕様(2026-08-21改訂: 一覧インライン編集にも対応)

- `app.record.create.submit` / `app.record.edit.submit` / `app.record.index.edit.submit`
  イベント(いずれもPC。モバイルは`mobile.app.record.create.submit`/
  `mobile.app.record.edit.submit`のみ、後述)でオフセット計算を実行する。通常の追加・編集画面
  ではCALCフィールドの値はブラウザ上でリアルタイムに再計算されているため、`event.record`から
  追加のAPI呼び出しなしにオフセット参照フィールドの最新値を読み取れる(REST API不要)。
- 出力先フィールドは常にプラグインが上書きする値なので、追加・編集画面(`create.show`/
  `edit.show`)および一覧画面のインライン編集(`app.record.index.edit.show`)で`disabled`にし、
  直接編集を禁止する(`text_slice`の「挿入先の編集を禁止」と同じ方針。目的が「基準フィールドから
  自動計算される値を絞り込みに使えるようにする」ことである以上、手動での不整合な値の入力を
  防ぐ意図)。ただし、この`disabled`化はJavaScript API(UIレベル)による制御であり、REST API
  経由での更新やアクセス権による制御ではない点をsecurity-checklist.mdに明記する。
- 基準フィールド自体は編集を禁止しない(通常のフィールドとして自由に入力・変更できる。一覧
  インライン編集でも同様)。
- 複数のルールが設定順に処理されるため、あるルールの出力先フィールドが別のルールの基準
  フィールドと同じ場合、後続のルールは**更新後の値**を参照する(意図的な仕様、チェーン計算を
  妨げない)。

### 一覧インライン編集(`app.record.index.edit.submit`)固有の注意点(確定)

kintoneドキュメントMCP「レコード一覧画面のインライン編集で保存するときのイベント」の制限事項に、
「イベントオブジェクトで取得できる計算フィールドの値は、操作するレコード一覧画面にフィールドを
配置しているかどうかで変わる(配置している場合: 空文字列/配置していない場合: 再計算前の値)」
と明記されている。これは通常の追加・編集画面(常にリアルタイム再計算される)とは異なる、
インライン編集固有の制限である。

- オフセット参照フィールドの値が**空文字列**になるケース(=一覧にそのCALCフィールドを配置している
  場合)は、既存の「オフセット値が数値として解決できない場合はスキップする」ロジックがそのまま
  安全に働く(誤った値を書き込むことはない)。
- 一方、**一覧に配置していない**CALCフィールドを参照する場合、値は「再計算前の値」(=保存前の
  古い値)のまま返るため、そのまま計算すると**古いオフセットに基づく誤った日付を無言で
  書き込んでしまう**リスクがある(これはスキップされず、一見正常な計算結果に見えてしまう点が
  危険)。
- そのため、`js/lib/offset-calculator.js`の`isUnreliableInlineEditOffset(rule, offsetFieldType)`で
  「インライン編集コンテキストかつオフセット参照フィールドがCALC型」を判定し、
  `app.record.index.edit.submit`ではこの条件に該当するルールを**計算せずスキップ**する
  (出力先フィールドを変更しない)。NUMBER型フィールドを参照するルール、および固定値(`FIXED`)の
  ルールはこの制限を受けないため、インライン編集でも通常どおり再計算される。

#### 2026-08-21再改訂: 設定画面でユーザーに明示する

ユーザーからの実機検証(app 736での`event.record`ダンプ)により、`isUnreliableInlineEditOffset`
によるスキップ自体は意図通り正しく機能している(`event.record`には出力先フィールドを含む
全フィールドが正しく含まれているが、CALCフィールドの値だけが上記の理由で信頼できない)ことが
確認された。当初「一覧画面で更新できていない」という報告を受けてREST API
(`kintone.api()`でのGET/PUT)への作り直しを検討したが、`event.record`自体は正しく、
このスキップは意図した安全な動作だったため**却下**した(REST APIは導入しない)。

本当の課題は、ユーザーがこの制限を設定時に知る手段が無かったことだった。そこで、
`js/config.js`の設定画面で、あるルールのオフセット参照フィールドが計算(CALC)フィールドの
場合に`isUnreliableInlineEditOffset`(同じ判定関数を再利用)でcaution(注意書き)を表示する
ようにした(ページ冒頭の説明文にも一言、該当ルール行のオフセット参照フィールド欄の直下にも
個別に表示する)。これにより、ロジック自体は変更せず、ユーザーが「一覧編集では再計算されない
組み合わせ」を設定時点で認識できるようにした。

さらに、実際にこのスキップが発生した**その場(一覧画面での保存時)でも**気づけるよう、
`desktop.js`の`applyRules()`はスキップが発生した出力先フィールドコードの配列を返すように変更し、
`app.record.index.edit.submit`ハンドラーはその配列が空でなければ`alert()`で
「計算(CALC)フィールドを参照するオフセット設定のため、この出力先フィールドは一覧画面の
インライン編集では再計算されなかった」旨を通知する。`event.error`(画面上部エラー)は使わない
(それを設定すると保存処理自体がキャンセルされてしまうため。基準フィールドの変更自体は正常な
操作であり、あくまで一部のルールが計算できなかったことを知らせるだけで保存は妨げない)。

## 対応画面(確定・スコープ、2026-08-21改訂)

- PC: レコード追加画面・レコード編集画面(`app.record.create.submit`/`app.record.edit.submit`、
  `app.record.create.show`/`app.record.edit.show`)に加え、一覧画面のインライン編集
  (`app.record.index.edit.show`で出力先フィールドを`disabled`化、`app.record.index.edit.submit`で
  再計算)にも対応する。基準フィールド側の`disabled`化は行わない(基準フィールドは一覧編集でも
  自由に編集できてよいため)。
- モバイル: レコード追加画面・レコード編集画面のみ(`mobile.app.record.create.submit`/
  `mobile.app.record.edit.submit`、`mobile.app.record.create.show`/`mobile.app.record.edit.show`)。
  モバイルには一覧画面のインライン編集が存在しないため対応不要。
- 一覧インライン編集でCALCフィールドをオフセット参照に使うルールは、上記「一覧インライン編集
  固有の注意点」の理由により計算をスキップする(出力先フィールドは変更されない)。固定値・
  NUMBERフィールド参照のルールは通常どおり再計算される。

## 設定画面

`kintone.plugin.app.setConfig()`にのみ保存する。`kintone.app.getFormFields()`(JavaScript API、
CLAUDE.md方針3)でフィールド一覧を取得する。

- ルールを追加・削除できる。ルールごとに:
  - 基準フィールド(DATE/DATETIME型から選択)
  - 単位(日数/分数)
  - オフセット値の種類(固定値/フィールド参照)をラジオボタンで選択、選択に応じて対応する
    入力欄(固定値の数値入力、またはフィールド参照のセレクト)のみ表示する
  - 固定値(数値、正負・小数可)
  - オフセット参照フィールド(NUMBER型、または表示書式が数値のCALC型から選択)
  - 出力先フィールド(DATE/DATETIME型から選択)
- 保存時に`js/lib/config-validation.js`でチェックする(基準/出力先フィールド未選択、
  基準フィールドと出力先フィールドの型不一致、単位`MINUTES`とDATE型の組み合わせ、
  出力先フィールドと基準フィールドの重複、出力先フィールドの重複、固定値が数値でない、
  フィールド参照時の参照フィールド未選択・対象外フィールド選択、等)。
- オフセット参照フィールドに計算(CALC)フィールドを選択したルールは、保存をブロックする
  エラーではなく、そのルール行に「一覧画面のインライン編集では再計算されない」旨のcaution
  (注意書き)を表示する(`js/config.js`の`applyCalcCautionVisibility()`、
  `OffsetCalculator.isUnreliableInlineEditOffset()`を再利用。2026-08-21追加、上記
  「一覧インライン編集固有の注意点」参照)。ページ冒頭の説明文にも同様の注意を一言記載する。

## エッジケース

- 基準フィールドの値が空: そのルールをスキップし、出力先フィールドは変更しない。
- オフセット参照フィールドの値が空/非数値: そのルールをスキップし、出力先フィールドは
  変更しない。
- 基準フィールド・出力先フィールド・オフセット参照フィールドのいずれかがフォームから削除された
  場合: `event.record`にそのフィールドコードが存在しないため早期リターンし、画面をクラッシュ
  させない。
- 出力先フィールドが複数のルールから書き込まれる設定(出力先の重複): 設定画面の保存時
  バリデーションで弾く(text_sliceと同じ、意図しない上書き競合を防ぐ)。
- 固定値に極端に大きい数値を入力した場合: `Date`が表現できる範囲(西暦270000年頃まで)を
  超えると`Invalid Date`になり得るが、業務データとして現実的でないため特別なガードは設けず、
  `Invalid Date`になった場合は出力先フィールドを更新しない(`applyOffset`が`null`を返す)。
- 一覧インライン編集でCALCフィールドをオフセット参照に使うルール: 上記「一覧インライン編集固有の
  注意点」の理由により計算をスキップする(出力先フィールドは変更しない)。

## 実装

kintoneドキュメントMCPを参照しながら実装した。確認済み事項:

- `app.record.create.submit`/`app.record.edit.submit`(PC)・`mobile.app.record.create.submit`/
  `mobile.app.record.edit.submit`(モバイル)は、イベントオブジェクトの`record`を書き換えて
  `return event`することで保存内容を上書きできる(添付ファイル情報は取得不可だが本プラグインは
  対象外のため無関係)。
- `kintone.app.getFormFields()`はREST API「フィールドを取得する」の`properties`と同様の値
  (フィールドコードをキーにした平坦なオブジェクト、`{properties: {...}}`のようにラップされない)
  を返す(CLAUDE.mdの既知の落とし穴、`text_slice`/`org_lookup`と同じ確認方法)。
- CALC(計算)フィールドの`properties.フィールドコード.format`に表示書式(`NUMBER`/`NUMBER_DIGIT`/
  `DATETIME`/`DATE`/`TIME`/`HOUR_MINUTE`/`DAY_HOUR_MINUTE`)が入ることを「フィールドを取得する」
  REST APIドキュメントで確認済み。オフセット参照フィールドの選択肢を`format`が`NUMBER`/
  `NUMBER_DIGIT`のCALCフィールドのみに絞り込むために使用する。
- NUMBER型・CALC型フィールドの値は文字列(例: `"123"`)であり、空文字列は「値なし」を表す
  (「フィールド形式」ページで確認済み)。`parseFloat()`で数値化し、`Number.isFinite()`で
  妥当性を確認する。
- CALCフィールド自体は値の登録・更新ができない(「フィールド形式」の登録・更新可否表で確認済み)。
  本プラグインはCALCフィールドを出力先にはできない設計のため無関係だが、オフセット参照フィールド
  としての読み取り専用利用のみ確認済み。
- `app.record.index.edit.submit`(一覧画面のインライン編集で保存するときのイベント、PC専用)は
  `event.record`の書き換え・`return event`による保存内容の上書きが`create.submit`/`edit.submit`
  と同じ形で可能であること、および制限事項として「配置していないCALCフィールドの値は再計算前の
  値のまま・配置している場合は空文字列になる」ことをkintoneドキュメントMCPで確認済み(上記
  「一覧インライン編集固有の注意点」参照)。

セキュアコーディングガイドラインでのリスクチェックは`security-checklist.md`を参照。

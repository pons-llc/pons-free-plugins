# 詳細カレンダープラグイン

## 機能概要

レコード一覧画面(**表形式**, `viewType: 'list'`)に、日付/日時フィールドを軸にした詳細なカレンダー(週表示・日表示)を表示する、**PC専用・表示専用**のプラグイン。グループ分け・色分け・タイトル/ホバー項目・クリックでのレコード詳細遷移に対応する。**ドラッグ&ドロップでの編集は行わない**(当初実装したが、スコープから外した。判断記録.md参照)。

- 対象は通常の一覧(表形式)。`app.record.index.show`イベントの`event.viewType === 'list'`のときのみ対象と判定し、`event.viewId`で**一覧ごとに表示設定を切り替えられる**(gantt_chart_viewと同じパターン。ユーザー指示により必須)。
- カレンダーは`kintone.app.getHeaderSpaceElement()`(「レコードの絞り込みやレコードの追加などを操作するメニュー」と「レコード一覧(表)」の間、フル幅で取得できる領域)に描画する。**ネイティブの表(一覧本体)はそのまま残し、非表示にはしない**(kintoneの内部DOM構造・クラス名に依存する非表示処理は壊れやすく、gantt_chart_view/hierarchy_viewも同様の理由でネイティブの一覧本体には手を入れていない。判断記録.md参照)。

## データ取得方針(JavaScript APIのみ・最大100件)

**REST APIは一切使わない。** 表示専用プラグインになったため、gantt_chart_view/hierarchy_view等の他プラグインと異なり例外的なREST API利用箇所も持たない。

- レコードは`app.record.index.show`イベントの`event.records`(現在ページの一覧に表示されているレコード配列。JavaScript APIの一部としてイベントオブジェクトに直接渡され、REST GETは発生しない)のみを使用する。`GET /k/v1/records.json`によるページング全件取得(gantt_chart_view方式)は**行わない**。
- 一覧の1ページあたりの表示件数は管理者がアプリ側で設定でき(最大500件)、`event.records`はその件数分すべて含まれ得るため、**本プラグインは描画対象を先頭100件に自主的に打ち切る**。カレンダーのツールバーに(常時)「表示中: n件 / 最大100件(REST API不使用のため)」のように、100件制限であることを明記する(ユーザー指示により必須)。
- 100件を超える一覧を扱いたい場合は、kintone側の一覧設定(絞り込み条件・ページ件数)を調整して対象レコードを100件以下に絞り込むよう、設定画面・個別ページにも案内文を記載する。

## レコード詳細画面への遷移

- イベントブロック/チップをクリックすると、`kintone.buildPageUrl('APP_DETAIL', { appId, recordId })`(JavaScript API)でURLを組み立て、同じタブで遷移する。

## 表示単位: 週表示・日表示、および日付ジャンプ

設定画面で既定の表示単位(週/日)を一覧ごとに設定でき、カレンダー画面上部のツールバーのボタンでも切り替えられる(ページ内の一時的な状態、リロードで既定値に戻る。gantt_chart_viewのスケール切り替えと同じ考え方)。

- ツールバーには「前へ/今日/次へ」ボタンに加えて、任意の日付へ直接ジャンプできる`<input type="date">`を設置する。日表示・週表示のどちらでも、前へ/次へ(1日または1週間ずつ)だけでは遠い日付へ辿り着きにくい(実際にユーザーから指摘があった)ため、日付を直接指定できるようにした。週表示でジャンプすると、その日付を含む週へ移動する。

### 日表示(day)

- 対象日(既定は本日)の0:00〜24:00を1時間刻みの時間軸として表示する。
- **グループ分けフィールドを軸として使う**。指定したグループ分けフィールドの値ごとに列(縦デザイン)または行(横デザイン)を作り、その中に該当レコードのイベントブロックを開始〜終了時刻に応じた位置・サイズで配置する。グループ未設定の場合は単一グループ(「すべて」)として扱う。

### 週表示(week)

- 対象週(既定は今週、日曜始まり)の日曜〜土曜、7つの日付セルを表示する。
- グループ分けフィールドが**未設定**、またはデータ上グループが1種類しかない場合は、日付だけを軸にしたシンプルな7セル表示にする(各日付セル内に、その日を開始日とするレコードのイベントチップを開始時刻順に縦積み(縦デザイン)または横並び(横デザイン)で表示)。
- グループ分けフィールドが設定されており、かつ2種類以上のグループが存在する場合は、**日付とグループの2軸グリッド**にする(ユーザー指示により追加)。日表示のグループ軸の向きの決め方と揃え、縦デザインは「グループ=列、曜日=行」、横デザインは「曜日=列、グループ=行」とする。セルの中身(イベントチップ)自体はシンプル表示のときと同じ。

## 縦/横デザイン

一覧ごとに設定画面で選択する(実行時切り替えは設けない)。

- **縦(vertical)**: 日表示は「グループ=列、時刻=縦軸」。週表示は「曜日=列(横に7日並ぶ)、各セル内は縦積み」。
- **横(horizontal)**: 日表示は「グループ=行、時刻=横軸」(ガントチャートに近い見た目)。週表示は「曜日=行(縦に7日並ぶ)、各セル内は横並び」。
- 横デザインの日表示は、グループ名ラベル(100px)+24時間分の時間軸(1440px)を横に並べた合計幅を、祖先要素すべてに明示的な`width`として持たせることで、`cv-scroll`の`overflow: auto`が正しく横スクロールバーを出すようにしている(明示しないと、途中の要素がflexboxの既定の伸縮挙動で親幅に収まるよう縮んでしまい、はみ出した部分が見切れてしまう不具合が実際に発生した)。グループ名ラベル列は、横スクロールしても常に見えるよう左端に固定(`position: sticky; left: 0`)している(縦デザインの列ヘッダーを上端に固定している`position: sticky; top: 0`と対になる対応)。

## タイトル・ホバー項目

- タイトルフィールド(必須、1つ): イベントブロックに表示するラベル。フィールド値は`js/lib/format-field-value.js`の`formatFieldValue()`で文字列化し、`textContent`でDOMへ挿入する(`innerHTML`不使用)。
- ホバー項目(任意、複数): ブロックの`title`属性(ブラウザ標準のツールチップ、DOM APIのプロパティ代入でHTMLエスケープの心配がない)に、ラベルと値を改行区切りで設定する。

## グループ分け・色分け(値ごとの色指定に対応)

- グループ分けフィールド(任意): 日表示の軸として使う。`USER_SELECT`(作業者相当)/`ORGANIZATION_SELECT`/`GROUP_SELECT`/`DROP_DOWN`/`RADIO_BUTTON`/`STATUS`。
- 色分けフィールド(任意、グループ分けフィールドとは独立): `STATUS`/`DROP_DOWN`/`RADIO_BUTTON`。未設定の場合はグループ分けフィールドの値で色分けする(フォールバック)。グループ分けとは別の観点(例: グループ分けは担当者、色分けはステータス)で色分けしたいケースに対応する(ユーザー指示により追加)。
- 色の割り当ては既定では固定パレットから値ごとに決定的に(ハッシュベースで)自動選択されるが、**管理者は設定画面で値ごとに色を選べる**。自由入力のカラーピッカーではなく、固定パレット(`js/lib/color-assignment.js`の`DEFAULT_PALETTE`、8色)から選ぶ`<select>`にしている(色の選び方をシンプルにするため。判断記録.md参照)。「(自動)」を選ぶと個別指定を解除し、自動割り当てに戻る。値ごとの色指定はDROP_DOWN/RADIO_BUTTONのみ対応する。STATUSの選択肢(プロセス管理のステータス名)はJavaScript APIから列挙する手段がなく、REST APIでの列挙(`GET /k/v1/app/status.json`)は「REST API不使用」の方針上避けたため、**STATUSを色分けフィールドに選んだ場合は自動色のみで、値ごとの手動指定はできない**(判断記録.md参照)。
- 色指定は`kintone.plugin.app.setConfig()`に`colorOverrides: { 値: '#rrggbb' }`として保存する。描画時、`js/lib/color-assignment.js`の`assignColors()`が保存済みの値のみ`#rgb`/`#rrggbb`形式かを検証してから使用する(保存済みJSONを直接改ざんされた場合の多層防御。CSSインジェクション対策)。
- カレンダーのツールバー直下に、色分けの凡例(値ごとの色スウォッチ+ラベル)を常時表示する(ユーザー指示により追加)。凡例は現在表示中の日/週だけでなく、取得済みレコード全体(最大100件)に含まれる値を対象にする(日/週を切り替えるたびに項目数が変わって見づらくならないようにするため)。

## 対象フィールド型

- 開始日時フィールド(必須): `DATE`または`DATETIME`。`DATE`のみの場合は終日イベントとして扱う。
- 終了日時フィールド(任意): `DATE`または`DATETIME`。未設定の場合、開始が`DATETIME`なら1時間、`DATE`なら1日の既定幅で表示する(ガントチャートプラグインの「終了日未設定→開始日と同じ1日」と同様の考え方)。
- タイトル・ホバー項目フィールド: `SUBTABLE`以外の全フィールド型を選択可能(ガントチャートプラグインの「バー内表示項目」と同じ方針)。

## 設定画面

対象一覧(view)ごとに、以下を設定する(`kintone.plugin.app.setConfig()`にのみ保存)。

- 対象一覧: **REST API(`GET /k/v1/app/views.json`)を使わずに指定する**ため、一覧IDを直接入力する数値欄(空欄で「すべて(デフォルト)」)とする。一覧IDの確認方法(対象の一覧を開いたときのブラウザURLの`view=`の数字)を設定画面に説明文として明記する(gantt_chart_viewはREST APIで一覧を列挙してドロップダウンにしているが、本プラグインは「REST APIを使わずJavaScript APIのみで実現する」というユーザー指示を、一覧の識別を含めて徹底するため、この点は意図的にgantt_chart_viewと異なる設計にした。判断記録.md参照)。
- タイトルフィールド(必須)
- 開始日時フィールド(必須)・終了日時フィールド(任意)
- グループ分けフィールド(任意)
- 色分けフィールド(任意)・値ごとの色指定(DROP_DOWN/RADIO_BUTTONのみ、フィールド選択時に選択肢が自動表示される)
- ホバー項目(複数選択可)
- 既定の表示単位(週/日)
- デザイン(縦/横)

保存時は`js/lib/config-validation.js`でバリデーションする(タイトル・開始日時の未選択、同一一覧IDの重複登録などをチェック)。

## 既知の制約・将来課題

- STATUSフィールドを色分けに使う場合、値ごとの手動色指定はできない(自動割り当てのみ。STATUSの選択肢をJavaScript APIから列挙する手段がないため。判断記録.md参照)。
- 月表示は将来課題(初期スコープ外)。
- 仮想スクロールは未実装。最大100件までのキャップにより深刻な性能劣化は想定していないが、実環境での描画性能は未検証。
- 一覧IDをURLから手動確認する運用は、gantt_chart_viewのドロップダウン選択と比べて管理者の手間が増える(REST不使用の設計判断とのトレードオフ)。
- ドラッグ&ドロップでの編集は行わない(表示専用。判断記録.md参照)。

## 実装で確認したkintone API仕様(kintoneドキュメントMCPで確認済み)

- `app.record.index.show`: `event.viewId`・`event.viewType`(`list`/`calendar`/`custom`)・`event.records`(`list`のときは現在ページのレコード配列。REST不要)を持つ。
- `kintone.app.getHeaderSpaceElement()`(PC専用): 「レコードの絞り込みやレコードの追加などを操作するメニュー」と「レコード一覧」の間の、フル幅の要素を取得できる。利用できる画面はレコード一覧画面のみ。
- `kintone.buildPageUrl('APP_DETAIL', { appId, recordId })`: レコード詳細画面のURLを非同期で組み立てる。JavaScript APIであり`GET`によるREST呼び出しは発生しない(ただし内部的にサーバーへの問い合わせを伴う非同期APIであり、ユーザーあたり1分50回の呼び出し上限がある。クリック時にのみ呼び出すため通常問題にならない)。
- `kintone.app.getFormFields()`(JS API): REST版`GET /k/v1/app/form/fields.json`の`properties`と同等の値を返す(戻り値自体が`properties`の中身であり、`{ properties: {...} }`のようにラップされない。CLAUDE.mdの既知の落とし穴)。DROP_DOWN/RADIO_BUTTONの`options`(選択肢)もここから取得できるが、STATUSフィールドには選択肢の列挙は含まれない。

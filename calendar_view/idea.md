# 詳細カレンダープラグイン

## 機能概要

レコード一覧画面(**表形式**, `viewType: 'list'`)に、日付/日時フィールドを軸にした詳細なカレンダー(週表示・日表示)を表示する、**PC専用**のプラグイン。グループ分け・タイトル/ホバー項目・クリックでのレコード詳細遷移・ドラッグ&ドロップでの日時変更に対応する。

- 対象は通常の一覧(表形式)。`app.record.index.show`イベントの`event.viewType === 'list'`のときのみ対象と判定し、`event.viewId`で**一覧ごとに表示設定を切り替えられる**(gantt_chart_viewと同じパターン。ユーザー指示により必須)。
- カレンダーは`kintone.app.getHeaderSpaceElement()`(「レコードの絞り込みやレコードの追加などを操作するメニュー」と「レコード一覧(表)」の間、フル幅で取得できる領域)に描画する。**ネイティブの表(一覧本体)はそのまま残し、非表示にはしない**(kintoneの内部DOM構造・クラス名に依存する非表示処理は壊れやすく、gantt_chart_view/hierarchy_viewも同様の理由でネイティブの一覧本体には手を入れていない。判断記録.md参照)。

## データ取得方針(JavaScript APIのみ・最大100件)

**REST APIは使わず、JavaScript APIのみでレコードを取得する。**

- レコードは`app.record.index.show`イベントの`event.records`(現在ページの一覧に表示されているレコード配列。JavaScript APIの一部としてイベントオブジェクトに直接渡され、REST GETは発生しない)のみを使用する。`GET /k/v1/records.json`によるページング全件取得(gantt_chart_view方式)は**行わない**。
- 一覧の1ページあたりの表示件数は管理者がアプリ側で設定でき(最大500件)、`event.records`はその件数分すべて含まれ得るため、**本プラグインは描画対象を先頭100件に自主的に打ち切る**。カレンダー描画領域のヘッダー(常時表示)に「⚠ 一覧の現在ページから最大100件まで表示しています(全n件中)」のように、100件制限であることを明記する(ユーザー指示により必須)。
- 100件を超える一覧を扱いたい場合は、kintone側の一覧設定(絞り込み条件・ページ件数)を調整して対象レコードを100件以下に絞り込むよう、設定画面・個別ページにも案内文を記載する。

## ドラッグ&ドロップ編集(唯一のREST API利用箇所)

- カレンダー上のイベントブロックをドラッグ&ドロップすると、ドロップ先の日時(および日表示でグループ軸に対応する場合はグループフィールドの値)に応じて、開始日時フィールド(・グループフィールド)を更新する。終了日時が設定されている場合は元の継続時間を維持して再計算する。
- **任意のレコード(現在編集画面を開いていないレコード)の値を更新するJavaScript APIは存在しない**ため、CLAUDE.mdの方針3(「REST APIはJavaScript APIで実現できない場合のみ使い、その際もkintone自身への呼び出しに限り`kintone.api()`を使用する」)に従い、この更新処理のみ`kintone.api()`経由で`PUT /k/v1/record.json`を呼び出す(hierarchy_viewの「保存」ボタンでの一括更新と同じ考え方の例外運用。ただし本プラグインはドラッグ&ドロップの都度、即時に1件ずつ更新する)。
- 更新時は取得済みレコードの`$revision`を指定し、競合(他ユーザーが同時に更新した場合)を検出したら`kintone.showNotification('ERROR', ...)`でエラーを通知し、カレンダーを再描画してドラッグ操作を取り消す(楽観的排他制御)。
- ドラッグ&ドロップの可否は設定画面で一覧ごとに有効/無効を切り替えられる(既定は無効。読み取り専用の一覧にも安全に導入できるようにするため)。
- 生の`fetch`/`XMLHttpRequest`は使用しない。`kintone.api()`のみ。

## レコード詳細画面への遷移

- イベントブロックをクリックすると、`kintone.buildPageUrl('APP_DETAIL', { appId, recordId })`(JavaScript API)でURLを組み立て、同じタブで遷移する。ドラッグ操作との判定は、HTML5標準のDrag and Drop API(`draggable`属性)を使うことで自前の移動量閾値計算なしに実現している(実際にドラッグ(`dragstart`発火)した場合はブラウザの標準挙動としてドロップ後に`click`が発火しないため。判断記録.md参照)。

## 表示単位: 週表示・日表示

設定画面で既定の表示単位(週/日)を一覧ごとに設定でき、カレンダー画面上部のツールバーのボタンでも切り替えられる(ページ内の一時的な状態、リロードで既定値に戻る。gantt_chart_viewのスケール切り替えと同じ考え方)。

### 日表示(day)

- 対象日(既定は本日、ツールバーの「前日/翌日/今日」ボタンで移動)の0:00〜24:00を1時間刻みの時間軸として表示する。
- **グループ分けフィールドを軸として使う**。指定したグループ分けフィールドの値ごとに列(縦デザイン)または行(横デザイン)を作り、その中に該当レコードのイベントブロックを開始〜終了時刻に応じた位置・サイズで配置する。グループ未設定の場合は単一グループ(「すべて」)として扱う。
- ドラッグ&ドロップで、時刻(15分刻みにスナップ)とグループ(列/行の移動)の両方を変更できる。グループフィールドへの反映は、グループフィールドが値を直接更新可能な型(ドロップダウン/ラジオボタン/ユーザー選択/組織選択/グループ選択)の場合のみ行う(ステータスなど直接更新できないフィールドをグループに指定した場合は、グループ軸の移動によるドラッグ&ドロップ更新を無効化し、時刻の変更のみ許可する)。

### 週表示(week)

- 対象週(既定は今週、日曜始まり。ツールバーの「前週/翌週/今週」ボタンで移動)の日曜〜土曜、7つの日付セルを表示する。
- **日付を軸として使う**(グループ分けフィールドは軸にせず、イベントブロックの色分け・ラベルとしてのみ反映する)。各日付セル内には、その日を開始日とするレコードのイベントブロックを開始時刻順に縦積み(縦デザイン)または横並び(横デザイン)で表示する。
- ドラッグ&ドロップで、別の日付セルへ移動すると開始日を変更する(時刻は保持)。終了日時が設定されている場合は同じ日数分ずらす。

## 縦/横デザイン

一覧ごとに設定画面で選択する(実行時切り替えは設けない)。

- **縦(vertical)**: 日表示は「グループ=列、時刻=縦軸」。週表示は「曜日=列(横に7日並ぶ)、各セル内は縦積み」。
- **横(horizontal)**: 日表示は「グループ=行、時刻=横軸」(ガントチャートに近い見た目)。週表示は「曜日=行(縦に7日並ぶ)、各セル内は横並び」。

## タイトル・ホバー項目

- タイトルフィールド(必須、1つ): イベントブロックに表示するラベル。フィールド値は`js/lib/format-field-value.js`の`formatFieldValue()`で文字列化し、`textContent`でDOMへ挿入する(`innerHTML`不使用)。
- ホバー項目(任意、複数): ブロックの`title`属性(ブラウザ標準のツールチップ、DOM APIのプロパティ代入でHTMLエスケープの心配がない)に、ラベルと値を改行区切りで設定する。

## 対象フィールド型

- 開始日時フィールド(必須): `DATE`または`DATETIME`。`DATE`のみの場合は終日イベントとして扱う。
- 終了日時フィールド(任意): `DATE`または`DATETIME`。未設定の場合、開始が`DATETIME`なら1時間、`DATE`なら1日の既定幅で表示する(ガントチャートプラグインの「終了日未設定→開始日と同じ1日」と同様の考え方)。
- グループ分けフィールド(任意): `USER_SELECT`(作業者相当)/`ORGANIZATION_SELECT`/`GROUP_SELECT`/`DROP_DOWN`/`RADIO_BUTTON`/`STATUS`。
- タイトル・ホバー項目フィールド: `SUBTABLE`以外の全フィールド型を選択可能(ガントチャートプラグインの「バー内表示項目」と同じ方針)。

## 設定画面

対象一覧(view)ごとに、以下を設定する(`kintone.plugin.app.setConfig()`にのみ保存)。

- 対象一覧: **REST API(`GET /k/v1/app/views.json`)を使わずに指定する**ため、一覧IDを直接入力する数値欄(空欄で「すべて(デフォルト)」)とする。一覧IDの確認方法(対象の一覧を開いたときのブラウザURLの`view=`の数字)を設定画面に説明文として明記する(gantt_chart_viewはREST APIで一覧を列挙してドロップダウンにしているが、本プラグインは「REST APIを使わずJavaScript APIのみで実現する」というユーザー指示を、一覧の識別を含めて徹底するため、この点は意図的にgantt_chart_viewと異なる設計にした。判断記録.md参照)。
- タイトルフィールド(必須)
- 開始日時フィールド(必須)・終了日時フィールド(任意)
- グループ分けフィールド(任意)
- ホバー項目(複数選択可)
- 既定の表示単位(週/日)
- デザイン(縦/横)
- ドラッグ&ドロップ編集の有効/無効(既定: 無効)

保存時は`js/lib/config-validation.js`でバリデーションする(タイトル・開始日時の未選択、同一一覧IDの重複登録などをチェック)。

## TDD

`src/js/lib/`配下の以下の純粋ロジックをJestでユニットテストする(`pnpm test`)。

- `view-resolution.js`: `event.viewId`と設定配列から対象の一覧設定を引き当てる(未一致時は「すべて」にフォールバック)
- `record-cap.js`: `event.records`を100件に打ち切るロジックと、打ち切りの有無・全件数を返す
- `format-field-value.js`: フィールド型ごとの表示用文字列化(ユーザー選択/組織選択/グループ選択/複数選択/日時等)
- `event-model.js`: レコード配列→カレンダー描画用データモデルへの変換(開始/終了日時の欠損処理・終日判定・既定幅の算出)
- `grouping.js`: グループ分けロジック(日表示のグループ軸生成、グループ未設定時の単一グループ化)
- `day-grid.js` / `week-grid.js`: 日表示の時刻→座標変換(15分スナップ含む)、週表示の日付→セル変換
- `drag-update.js`: ドラッグ&ドロップの移動量(ピクセル・セル)から、更新後の開始/終了日時・グループ値を計算する(縦/横デザイン・日/週表示それぞれの座標系に対応)
- `config-store.js`: `getConfig()`が`null`を返す場合の既定値フォールバックを含む設定の読み書き
- `config-validation.js`: 設定画面のバリデーション

kintone依存のグルーコード(`js/calendar-render.js`(ドラッグ&ドロップのDOMイベント配線も含む)、`js/record-update.js`、`js/desktop.js`、`js/config.js`)は、Puppeteerによる実環境テスト(`pnpm run test:e2e`)で別途検証する(設定画面の保存・反映とレコード一覧画面での描画は実施済み。ドラッグ&ドロップ自体の自動テストはスコープ外、security-checklist.md参照)。

## 既知の制約・将来課題

- 時刻のドラッグ&ドロップは15分刻み固定(設定不可)。
- 週表示ではグループ分けを軸にしない(色分けのみ)。日表示との一貫性より実装・操作性のシンプルさを優先した設計判断(判断記録.md参照)。
- 月表示は将来課題(初期スコープ外)。
- 仮想スクロールは未実装。最大100件までのキャップにより深刻な性能劣化は想定していないが、実環境での描画性能は未検証。
- 一覧IDをURLから手動確認する運用は、gantt_chart_viewのドロップダウン選択と比べて管理者の手間が増える(REST不使用の設計判断とのトレードオフ)。

## 実装で確認したkintone API仕様(kintoneドキュメントMCPで確認済み)

- `app.record.index.show`: `event.viewId`・`event.viewType`(`list`/`calendar`/`custom`)・`event.records`(`list`のときは現在ページのレコード配列。REST不要)を持つ。
- `kintone.app.getHeaderSpaceElement()`(PC専用): 「レコードの絞り込みやレコードの追加などを操作するメニュー」と「レコード一覧」の間の、フル幅の要素を取得できる。利用できる画面はレコード一覧画面のみ。
- `kintone.buildPageUrl('APP_DETAIL', { appId, recordId })`: レコード詳細画面のURLを非同期で組み立てる。JavaScript APIであり`GET`によるREST呼び出しは発生しない(ただし内部的にサーバーへの問い合わせを伴う非同期APIであり、ユーザーあたり1分50回の呼び出し上限がある。クリック時にのみ呼び出すため通常問題にならない)。
- `PUT /k/v1/record.json`(REST、`kintone.api()`経由): `id`・`record`・`revision`を指定して1件更新。ステータス・作成者・更新者・更新日時・ルックアップ元コピー項目等は更新不可。
- `kintone.app.getFormFields()`(JS API): REST版`GET /k/v1/app/form/fields.json`の`properties`と同等の値を返す(戻り値自体が`properties`の中身であり、`{ properties: {...} }`のようにラップされない。CLAUDE.mdの既知の落とし穴)。

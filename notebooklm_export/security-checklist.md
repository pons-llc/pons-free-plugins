# notebooklm_export セキュリティチェックリスト

[secureCodingGuideline.md](../secureCodingGuideline.md)の一般項目([box_gdrive_iframe/security-checklist.md](../box_gdrive_iframe/security-checklist.md)参照、UTF-8/BOMなし・名前空間分離・`'use strict'`・外部スクリプト不使用などは同様に満たしている)は重複記載を省略し、本プラグイン固有の項目のみ記載する。

最終確認日: 2026-07-26

## コーディング作法

- [x] 文字コードはUTF-8(BOMなし)
- [x] グローバル変数を作らず、即時関数(IIFE)+名前空間オブジェクト(`window.NotebooklmExport`)のみを公開している(`js/lib/`配下の各ファイル)
- [x] 既存のkintoneグローバルオブジェクトを書き換え・参照していない
- [x] `'use strict'`を全JSファイルの先頭で使用している
- [x] 機能はプラグイン設定画面(config)のみで完結し、レコード一覧・詳細・追加・編集画面には一切手を加えない(`manifest.json`に`desktop`/`mobile`を持たない。ビルドで問題なくパッケージ化できることを確認済み)

## REST API・外部通信(CLAUDE.md開発方針3・9参照)

- [x] アプリIDを指定して任意のアプリの設計情報を取得できるJavaScript APIは存在しない(`kintone.app.getFormFields()`等は現在開いているアプリ専用)ため、起点アプリ・関連アプリを問わずREST API(`kintone.api()`、kintone自身への呼び出し専用の内部ラッパー)に統一している。生の`fetch`/`XMLHttpRequest`でURLを直接組み立てていない(`js/config.js`の`safeApiCall`)
- [x] `kintone.api.url(path, true)`の第2引数`true`によりドメイン部分を自動解決させ、外部ドメインへのリクエストになる余地をコード上排除している
- [x] 唯一の例外(`GET /k/v1/file.json`、カスタマイズファイル本体のダウンロード)は、公式ドキュメントで`kintone.api()`が「利用できないAPI」と明記されているための対応であり、`excel_report_export`・`delete_backup`と同じパターンで`kintone.api.url()`が組み立てたkintone自身のURLへ`fetch()`する。宛先が固定でありユーザー入力や外部ドメインを一切含まない
- [x] kintone以外の外部サーバーへの通信(fetch/XHR)を一切行わない。カスタマイズ設定の`type: "URL"`(外部URL指定)の要素は、URLをテキストとして出力ファイルに記載するのみでアクセスしない(`js/lib/collect-customize-files.js`)
- [x] 外部ライブラリを一切使用していない(vanilla JSのみ)。ZIP生成(`js/lib/build-zip.js`・`js/lib/crc32.js`)は`delete_backup`の実装(外部ライブラリ不使用・格納方式のみの自前実装)をそのまま流用している
- [x] すべてのREST呼び出しはGET(取得)のみで、レコードやアプリ設定を変更するリクエスト(POST/PUT/DELETE)は一切送信しない

## 探索範囲の制御(暴走防止)

- [x] ルックアップ/関連レコード一覧フィールドを再帰的に辿る際、訪問済みアプリIDの集合(`js/lib/traverse-apps.js`)により同一アプリを2度取得することはなく、循環参照(自己参照を含む)があっても無限ループにならないことをJestで確定的に検証済み(`__tests__/traverse-apps.test.js`)
- [x] 探索するアプリの総数(訪問済み+探索待ちの合計)に上限(30アプリ)を設けており、大規模環境で意図せず大量のAPI呼び出しが発生することを防いでいる。上限到達時は打ち切り、メタデータファイルに未処理のアプリIDを記録する(idea.md「エッジケース」参照)

## 実データ・ドキュメントに基づく実装(推測実装の防止)

- [x] 取得する12種類のREST APIのレスポンス形式・必要アクセス権はすべてkintoneドキュメントMCPで確認済み(idea.md「取得する設計情報」の表に記載)
- [x] フィールドのアクセス権(`GET /k/v1/field/acl.json`)のみ、他の11項目と異なり動作テスト環境(`/preview/`)のURLが存在しないことをkintoneドキュメントMCPで確認済み。実装(`js/config.js`)も他の項目とは異なりプレビュー無しのURLを使用しており、出力ファイル・設定画面の説明文にもこの違いを明記している(idea.md参照)
- [x] ルックアップフィールドは「コピー元のフィールドのフィールドタイプ」で`type`が返り、`type`では判定できないことをkintoneドキュメントMCPで確認済み。`js/lib/extract-related-app-ids.js`は`lookup`プロパティの有無で判定しており、Jestでこの前提を明示的に検証済み

## 権限・部分的失敗の扱い(このプラグイン特有の設計判断)

- [x] 関連アプリについては、起点アプリの管理者と同じユーザーがアプリ管理権限を持つとは限らない(ルックアップ/関連レコード一覧が非nullになる条件はレコード閲覧・追加・アプリ管理権限のいずれか1つであり、アプリ管理権限を含意しない)。動作テスト環境の設定取得・ACL系APIは「アプリ管理権限」を要求するため、関連アプリで403エラーになるケースを想定し、`js/config.js`の`safeApiCall`で項目ごとにtry/catchしている。1項目・1アプリの取得失敗が他の項目・他のアプリの処理やzip生成全体を止めないことを`__tests__/traverse-apps.test.js`・`__tests__/build-app-result.test.js`で確認済み
- [x] 取得に失敗した項目は、出力ファイル内に「取得できませんでした(エラー内容)。アプリ管理権限が無い可能性があります。」と明記し、取得できなかったことが利用者に分かるようにしている(黙って空扱いにしない。`js/lib/render-app-document.js`)
- [x] 真の権限境界は常にkintone自身のREST API(アプリ管理権限の要求)に委ねており、本プラグインのUI側で権限制御を代替・迂回する実装はしていない(`plugin_catalog_builder`の設計判断と同様)

## XSS・CSSインジェクション対策

- [x] 設定画面(`js/config.js`)でエラー・進捗メッセージを描画する箇所はすべて`textContent`のみを使用しており、`innerHTML`は一切使用していない
- [x] 取得した設計情報(アプリ名・フィールド名・カスタマイズファイルの中身・ユーザー名等、他ユーザーが設定した文字列を含みうる)は、この設定画面のDOMには一切描画されない。すべてJSON文字列化・テキスト連結のみでMarkdown本文(`js/lib/render-app-document.js`・`js/lib/render-metadata-document.js`)を組み立て、Blobとしてダウンロードさせるだけであり、ブラウザがHTMLとして解釈する経路が存在しないためXSSのリスクがない
- [x] ダウンロード用のBlob URLは自プラグインが生成したバイト列のみから作成しており、外部由来のURLや文字列をそのまま`href`/`src`に渡す箇所はない

## 設定の妥当性検証

- [x] 保存する設定項目は「出力形式」(`txt`/`md`)のみで、`js/lib/config-store.js`の`load()`は未設定・不正値のいずれでも例外を投げず既定値(`txt`)にフォールバックする
- [x] `toRawConfig()`も同様に不正な値を`txt`にフォールバックしてから保存するため、`kintone.plugin.app.setConfig()`に想定外の値が渡ることはない

## 通信・認証情報の取り扱い

- [x] `kintone.api()`・`fetch()`(file.json)はいずれもログイン中のセッション情報を自動的に使用するため、APIトークンやパスワード等の認証情報をコード・設定に含めない(secureCodingGuideline.md準拠)
- [x] `.env`の検証環境接続情報(`KINTONE_USERNAME`/`KINTONE_PASSWORD`等)はプラグイン本体のコードに一切含まれず、E2Eテスト(Puppeteer、Node側)からのみ参照する

## ダウンロードされるファイルの機微情報に関する注意(個別確認事項)

- 出力されるzipには、アプリのアクセス権設定・通知先(ユーザーのログイン名・組織コード・グループコード)・条件式(`filterCond`、業務ロジックを含みうる)・カスタマイズJS/CSSのソースコードなど、社内的に機微な情報が含まれうる。これらはいずれも、ダウンロードを実行したユーザーが元々アプリ管理権限を通じて閲覧可能な情報の範囲内であり、本プラグインが新たな権限昇格を生むものではないが、**ダウンロードしたzipファイル自体の保管・共有(NotebookLM等の外部AIツールへのアップロードを含む)は利用者側の責任で適切に行う必要がある**旨を設定画面の説明文に明記した
- カスタマイズファイルの実体(JS/CSS)をそのまま埋め込むため、社外秘のロジックが含まれる場合はダウンロード先・共有範囲に注意する必要がある(設定画面の説明文で言及)

問題があれば、公開サイトのリポジトリのGitHub Issueで報告してもらい対応する。

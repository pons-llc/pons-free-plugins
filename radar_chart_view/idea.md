# レーダーチャートプラグイン

## 機能概要

レコード一覧画面(**表形式**, `viewType: 'list'`のみ対象。カレンダー形式・カスタマイズビューは対象外)に
設置したボタンを押すと、3〜8角形のレーダーチャート(集計軸ごとの多角形グラフ)を**別タブに開く
自己完結型のHTMLファイル**として生成する、PC専用・表示専用のプラグイン。

- ボタンは`kintone.app.getHeaderSpaceElement()`(一覧画面PC専用、`excel_report_export`と同じ設置場所)
  に設置する。`app.record.index.show`のたびに発火するため、二重追加を防ぐ(`excel_report_export`と
  同じガード方式)。
- ボタン押下後、対象レコードの選択(2択)をその場に簡易メニュー(2つのボタン)で表示する。
  - **表示中のレコード**: `event.records`(現在ページに表示されている行)をそのまま使う。
  - **絞り込み条件の全件**: `kintone.app.getQueryCondition()`で現在の絞り込み条件を取得し、
    `$id`昇順ページングで全件取得する(`gantt_chart_view`の`js/lib/paging-query.js`/`js/full-fetch.js`
    をそのまま流用)。件数上限は設定画面で指定する(既定値2000件、上限到達時は打ち切りをHTML内に表示)。
- 選択後、生成したHTML文字列を`Blob`化し、`URL.createObjectURL()`で得たURLを新しいタブに開く。
  - **ポップアップブロック対策**: 「表示中のレコード」「絞り込み条件の全件」のどちらも
    `kintone.app.getFormFields()`(軸ラベル解決用)の非同期呼び出しを挟むため、取得完了後に
    `window.open()`すると多くのブラウザでポップアップブロックの対象になりうる。これを避けるため、
    **どちらの選択でも**選択ボタン押下(ユーザー操作)の同期コールバック内で**先に
    `window.open('', '_blank')`し、空のタブへの参照を保持**しておき(取得中は簡易メッセージを表示)、
    必要なデータ(フォーム項目・「全件」の場合はレコード全件)の取得が完了してから、その参照に対して
    `win.location.href = blobUrl`でHTMLへ遷移させる。`kintone.app.getFormFields()`は
    `app.record.index.show`の時点で先読み(プリフェッチ)してキャッシュしておくため、実際には
    「表示中のレコード」選択時はキャッシュ済みで即座に遷移できることが多い。

## 設定画面(`kintone.plugin.app.setConfig()`に保存)

単一の設定オブジェクト(`gantt_chart_view`のような一覧ごとの配列ではなく、アプリ全体で1つ)。

| 項目 | 説明 |
| :-- | :-- |
| グルーピング単位 | 「レコードごと(グルーピングなし)」または「フィールドごと」の二択。フィールドごとを選ぶと、ラジオボタン/ドロップダウンのフィールドを1つだけ指定する(必須) |
| 集計用フィールド(軸) | 数値(`NUMBER`)フィールドを3〜8個、順序付きで選択する(軸1〜軸8の8個の選択欄。先頭から詰めて選ぶ、軸1〜軸3は必須)。選択順=レーダーチャートの頂点順 |
| 目盛数 | 目盛(同心多角形の分割数)。2〜10の整数、既定値5 |
| タイトル | チャートのタイトル文字列(生成HTMLの`<title>`/見出しに使う)。未入力なら既定タイトルを使う |
| 表示するバッジフィールド | 任意のフィールドを複数選択。**グルーピング単位が「レコードごと」のときのみ使用**し、選択フィールドの値を生成HTMLの**カード自体のバッジ(チップ)**として表示する(頂点や凡例の1行に押し込めたラベルにはしない。バッジが1つも無い場合はレコード番号`$id`をカードの見出しにフォールバックする)。「フィールドごと」グルーピングのときはグループ化フィールドの値自体がカードの見出しになるため、この設定は使用しない(設定画面上は残しておくが、フィールドごとグルーピング時は無視される旨を注記する) |
| 全件取得の上限件数 | 「絞り込み条件の全件」選択時の取得上限(既定値2000件) |

バリデーション(`js/lib/config-validation.js`、保存時に`js/config.js`から呼ぶ):

- 集計用フィールドは3〜8個・重複なし・すべて`NUMBER`型であること
- グルーピング単位が「フィールドごと」の場合、グルーピングフィールドは必須かつ`RADIO_BUTTON`/`DROP_DOWN`型であること
- 目盛数は2〜10の整数
- 全件取得上限は1以上の整数

## グルーピングと集計仕様

- **レコードごと**: 1レコード=1系列(カード1枚・多角形1つ)。値は各軸フィールドの生値(数値でなければ0扱い)。
- **フィールドごと**: グルーピングフィールドの値ごとにレコードをまとめ、1グループ=1系列(カード1枚・多角形1つ)。
  各軸フィールドの値は、グループ内レコードの**合計値**を基本の集計値として保持し、生成後のHTML画面上で
  「合計/平均」をトグルボタンで切り替えて表示できる(平均=合計/グループ内件数)。グルーピングフィールドが
  空文字列のレコードは「(未設定)」というグループにまとめる。
  - レコードごとグルーピングの場合、常にグループ内件数=1なので合計=平均となり、トグルは意味を持たない
    ため生成HTML側でトグル自体を非表示にする。

## 生成HTMLの表示形式(カード形式)とインタラクティブ機能

系列(レコードまたはグループ)ごとに、小さなレーダーチャートを1枚の**カード**としてグリッド状に
並べる(1つの大きな重ね描きチャート+凡例、ではない)。バッジ(表示するバッジフィールド)は
各カードの見出し部分にチップとして表示し、頂点や凡例の1行に詰め込んだラベルにはしない。

生成される単体HTMLファイルは外部通信・外部ライブラリを一切使わない自己完結ファイルで、以下の
操作をページ内(素のJS)で提供する。

- 目盛の合計/平均表示切り替え(フィールドごとグルーピング時のみ表示。全カード共通で切り替わる)
- カードごとのチェックボックスによる表示/非表示切り替え(非表示にしてもカード自体は残り、
  半透明〈dimmed〉になるだけ。再度チェックすればいつでも戻せる。チェックのたびに目盛の
  最大値〈スケール〉が変動しないよう、スケールは表示/非表示に関わらず全系列から算出する)
- 系列(カード)の並べ替え(元の順序/ラベル昇順/合計値降順/合計値昇順のプルダウン)

## 生成HTMLのセキュリティ設計(重要)

生成HTMLはレコードの値(ユーザー入力に由来する任意の文字列)を含むため、文字列結合によるHTML生成は
XSSリスクが高い。以下の方針で対策する(詳細は[security-checklist.md](security-checklist.md)参照)。

- HTMLの外殻(`<!doctype>`〜`</html>`、`<style>`、描画・操作ロジックの`<script>`)は**完全に静的な
  固定文字列**とし、実行時のレコード値を一切埋め込まない(`js/lib/standalone-page-script.js`に
  静的なJS文字列として定義)。
- 動的データ(タイトル・軸ラベル・系列ラベル・数値)は、`<script type="application/json" id="radar-data">`
  内にJSON文字列として埋め込む1箇所のみに限定する。`JSON.stringify()`は`</`をエスケープしないため、
  `</script>`によるタグ脱出を防ぐために`</`を`<\/`に置換してから埋め込む(`js/lib/html-template.js`)。
- 埋め込んだJSONは、静的な描画スクリプト側で`JSON.parse(...)`してからDOM APIで描画する。ラベルや
  数値の反映は必ず`textContent`(SVGは`createElementNS`+`textContent`)で行い、`innerHTML`/
  `insertAdjacentHTML`は一切使用しない(`gantt_chart_view`の描画方針を踏襲)。

## 対象外・既知の制約

- モバイルは非対応(`kintone.app.getHeaderSpaceElement()`はPC専用。将来対応する場合はモバイル一覧
  画面向けの別要素取得APIの調査が必要)。
- 対象は表形式(`viewType === 'list'`)のみ。カレンダー形式・カスタマイズビューは非対応
  (`event.records`の形が異なるため。`gantt_chart_view`と同じ制約)。
- サブテーブル内の数値フィールドは軸に選択できない(`kintone.app.getFormFields()`のトップレベル項目
  のみを対象とする)。
- 生成したHTMLファイルはその場限りで、kintone側には一切保存しない(ダウンロード・保存するかどうかは
  ブラウザの「名前を付けて保存」に委ねる)。

## TDD

`src/js/lib/`配下の以下の純粋ロジックをJestでユニットテストする(`pnpm test`)。

- `config-store.js`: 設定の読み書き・既定値
- `config-validation.js`: 設定のバリデーション(軸フィールド3〜8件・型・グルーピング必須項目・目盛数・上限件数)
- `series-builder.js`: レコード配列→系列データへの変換(レコードごと/フィールドごとの2モード、
  未設定グループへの集約、合計値・件数の算出)
- `radar-geometry.js`: 軸数(3〜8)に応じた頂点角度・座標計算、同心グリッド(目盛)座標計算
- `radar-stats.js`: 系列の合計値/平均値表示への変換
- `series-filter-sort.js`: 系列の並べ替え(元順序/ラベル/合計値昇順・降順)。表示/非表示は
  カードに`is-hidden-series`クラスを付けてdimmedにする方式(標準スクリプト側でのみ実装)のため、
  このファイルには含めない
- `html-template.js`: 静的HTML外殻+JSON埋め込み(`</`エスケープ含む)の組み立て

`js/lib/paging-query.js`・`js/full-fetch.js`は`gantt_chart_view`からそのままコピーして流用する
(全件取得の方針が同じため)。kintone依存のグルーコード(`desktop.js`/`config.js`、実際の
`window.open`/Blob生成)はPuppeteer E2E(`pnpm run test:e2e`)で実環境確認する。

## 実装で確認したkintone API仕様(kintoneドキュメントMCPで確認済み)

- `app.record.index.show`: `event.viewType`が`list`のとき`event.records`はレコードデータの配列
  (REST APIのレコードのフィールド形式と同様)。`calendar`のときは日付文字列をキーに持つオブジェクト、
  `custom`はページネーション有無で配列/空配列と、`list`以外は形が異なるため対象外とする根拠。
- `kintone.app.getHeaderSpaceElement()`(PC専用、レコード一覧画面で利用可): ヘッダー領域の要素を取得。
  `excel_report_export`が一括ダウンロードボタンの設置に使用している実績あり。
- `kintone.app.getQueryCondition()`: 絞り込み条件のみ(`order by`/`limit`/`offset`を含まない)を取得。
  `gantt_chart_view`/`excel_report_export`の全件取得で使用している既存パターンを流用。
- `GET /k/v1/records.json`: 1回の取得上限500件、`offset`上限1万件のため`$id`昇順ページングを使う
  (`gantt_chart_view`と同じ方針)。
- `kintone.app.getFormFields()`(JS API): トップレベルのフィールド定義を取得し、軸候補
  (`type === 'NUMBER'`)・グルーピング候補(`type`が`RADIO_BUTTON`/`DROP_DOWN`)・バッジ候補
  (全フィールド)の絞り込みに使う。戻り値はプロパティ名でラップされない(戻り値そのものが
  `properties`相当の値。CLAUDE.md記載の既知の落とし穴、`gantt_chart_view`のコメントと同じ確認済み仕様)。

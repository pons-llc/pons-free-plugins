# cross_app_check セキュリティチェックリスト

[secureCodingGuideline.md](../secureCodingGuideline.md)の一般項目([box_gdrive_iframe/security-checklist.md](../box_gdrive_iframe/security-checklist.md)参照、UTF-8/BOMなし・名前空間分離(`window.CrossAppCheck`)・`'use strict'`・外部スクリプト不使用などは同様に満たしている)は重複記載を省略し、本プラグイン固有の項目のみ記載する。

最終確認日: 2026-08-18 / 対象: 初回実装＋「突合設定をレコード単位に持つ」変更時点

## 添付ファイル(結果JSON)を「信用できない入力」として扱う(本プラグイン固有の最大のリスク)

突合結果は集計アプリのサブテーブルに添付ファイルとして保存され、ビューワはそれを読み込んで
画面に描画する。**添付ファイルは、そのレコードの編集権限を持つ人が任意の内容に差し替えられる。**
つまりビューワへの入力は「プラグインが書いたもの」とは限らない。

- [x] 添付ファイルの中身は必ず`js/lib/result-schema.js`の`parse()`を通してから描画する
      (`js/result-view.js`の`loadRun()`)。`parse()`は
      (1) JSONとして読めるか (2) オブジェクトか (3) `schemaVersion`が対応値か
      を確認したうえで`sanitize()`で全項目の型を正規化する。いずれかに反すれば例外を投げ、
      画面にはエラーメッセージだけを出して描画しない。
- [x] **レコードIDは`/^[0-9]+$/`にマッチするものだけを通す**(`asRecordIds()`)。
      レコードIDはレコード詳細画面へのリンク(`href`)の組み立てに使うため、
      `javascript:` スキームや相対パス片(`../../`)が混入すると
      XSS・オープンリダイレクトの経路になりうる。数字以外は配列から落としている。
- [x] **アプリIDも同様に`/^[0-9]+$/`のみ通す**(`asAppId()`)。数字でなければ空文字にする。
- [x] リンクを実際に組み立てる`js/result-view.js`の`recordLink()`でも、
      `href`に値を入れる直前に再度`/^[0-9]+$/`を確認している(多層防御)。
      検証に通らない場合はアンカーではなく`<span>`として描画し、`href`を作らない。
      外部リンクには`rel="noopener noreferrer"`を付けている。
- [x] `submitted`は真偽値以外をすべて`false`に倒し、件数は非負整数に丸める。
      行の`targets`配列は対象アプリの数に合わせて長さを揃えるため、
      短い/長い配列を渡されても描画側で添字外アクセスが起きない。
- [x] 検証済みかどうかを取り違えないよう、`js/file-client.js`の`downloadText()`に
      「呼び出し元は必ず ResultSchema.parse() を通してから描画すること」とコメントを残している。

## XSS(結果の描画)

- [x] 結果ビューワ(`js/result-view.js`)は`document.createElement()`と`textContent`のみで
      DOMを組み立てており、`innerHTML`・`insertAdjacentHTML`・`document.write`を一切使っていない。
      氏名・突合キー・アプリ名・ラベルはすべて外部由来(他アプリのレコード値/管理者入力)なので、
      HTML特殊文字が含まれていても文字列として表示される。
- [x] 要素を空にする箇所は`el.textContent = ''`で行っており、`innerHTML = ''`も使っていない。
- [x] 設定画面(`js/config.js`)でもフィールドラベル・フィールドコード・エラーメッセージは
      すべて`textContent`で出力している(`buildOptions()`、`setError()`)。
- [x] CSSインジェクション対策として、外部由来の文字列をstyle属性やCSS値に埋め込んでいない
      (状態表示の色分けは固定のクラス名`cac-status-ok`/`cac-status-ng`の付け替えのみ)。

## CSVインジェクション

- [x] CSV出力(`js/lib/csv.js`)では、`=` `+` `-` `@` `Tab` `CR` で始まる値の先頭に
      シングルクォートを付けて無害化している。氏名や突合キーに`=cmd|...`のような値が
      入っていた場合、Excelで開いた際に数式として実行されるのを防ぐため。
- [x] カンマ・ダブルクォート・改行を含む値はRFC 4180に従って引用符で囲み、
      値中のダブルクォートは2つ重ねてエスケープしている。

## REST API利用

- [x] kintoneへのAPI呼び出しは、ファイルAPI以外すべて`kintone.api()`(内部向けラッパー)経由で
      行い、生の`fetch`/`XHR`でURLを組み立てていない(`js/records-client.js`、
      `js/schema-writer.js`、`js/config.js`)。CLAUDE.md開発方針3のとおり、
      集計アプリ自身のフィールド一覧は`kintone.app.getFormFields()`(JavaScript API)を使い、
      別アプリのフィールド一覧・レコード取得のみREST APIを使っている。
- [x] **ファイルのアップロード/ダウンロードのみ生の`fetch`を使う**(`js/file-client.js`)。
      これはkintone公式ドキュメントに「このAPIは、kintone REST APIリクエストを送信するAPIでは
      実行できません」と明記されているため。URLは`kintone.api.url()`で組み立てており、
      同一オリジン(kintone自身)への相対パスのみ。外部ドメインへは一切送信していない。
      POSTには`kintone.getRequestToken()`によるCSRFトークンを付与している。
      `fileKey`は`encodeURIComponent()`でエスケープしてからクエリに載せている。
- [x] レコード取得のページングは`$id`昇順(`$id > 直前取得分の最大$id`)で行っており、
      `offset`の上限(10,000件)に達して取得が止まる問題が起きない(`js/lib/id-paging.js`)。
- [x] レコード取得は`for`文による逐次実行で、対象アプリを並列に叩いていない
      (`js/reconcile-runner.js`、`js/records-client.js`)。secureCodingGuideline.mdの
      「短時間で大量のリクエスト送信を避ける」「並列で実行するのをなるべく避ける」に対応。
- [x] 1アプリあたりの読み込み件数に上限(既定5000件、設定可能)を設け、到達したら打ち切って
      画面に警告を出す。無制限に取得し続けてブラウザを固めることがない。
- [x] 履歴テーブルの行数に上限(既定20件)を設けている。kintone公式が
      「1つのテーブルに大量の行を追加しないでください」と明記しているため。

## アプリ設定の書き換え(集計用フィールドの自動生成)

- [x] フィールド・レイアウトの変更は**設定画面から管理者が明示的にボタンを押したときだけ**行う
      (`js/schema-writer.js`の`ensureSchema()`)。レコード画面側からは一切行わない。
- [x] 実行前に`window.confirm()`で「アプリの設定が運用環境へ反映(デプロイ)される。
      動作テスト環境に未反映の変更がある場合、それらも同時に公開される」と明示して同意を取る。
      黙って他人の未公開の変更を公開してしまわないようにするため。
- [x] 追加するのは**不足しているフィールドだけ**で、既存フィールドの設定は変更・削除しない
      (`js/lib/app-schema.js`の`missingFieldProperties()`。`ensureFormFields`と同じ冪等方針)。
      同名のフィールドが別の型で既に存在する場合は追加対象から外し、
      テーブルの中身が欠けている場合はエラーメッセージを出して手動対応を促す(自動で作り直さない)。
- [x] 変更対象は`kintone.app.getId()`で得た**このプラグインが動作しているアプリ自身のみ**で、
      設定値のアプリID(基準アプリ・対象アプリ)に対しては書き込みを一切行わない
      (基準/対象アプリへの操作は`GET`のみ)。
- [x] このAPIにはアプリ管理権限が必要で、プラグイン設定画面はもともとアプリ管理者しか
      開けないため、権限の昇格は発生しない。

## レコード単位の突合設定(cac_definition)

突合の定義はプラグイン設定ではなく、レコードの`cac_definition`(文字列・複数行)にJSONで持つ。
つまり**そのレコードを編集できる人が、突合設定を書き換えられる**。

- [x] `cac_definition`の中身は信用せず、`js/lib/definition-store.js`の`normalize()`で
      定義済みのキー・型だけに揃えてから使う。未知のキーは持ち越さない。
      壊れたJSONは例外を握って空の設定として扱い、画面が必ず開けるようにしている。
- [x] 突合の実行前にも`js/lib/definition-validation.js`で検証し、
      不正な設定のままAPIを呼ばない(`js/desktop.js`の`runReconcile()`)。
- [x] アプリIDは`/^[0-9]+$/`で検証する。設定値のアプリIDはREST APIの`app`パラメーターに
      渡るだけで、URLの組み立てには使わない。
- [x] 設定を書き換えられても、読み書きできる範囲は**その利用者自身の権限の範囲**を超えない。
      基準アプリ・対象アプリのレコード取得はログインユーザーの権限で実行されるため、
      閲覧権限のないアプリを指定してもAPIがエラーを返すだけで、情報は取得できない。
- [!] 逆に言うと、**閲覧権限を持つアプリであれば任意のアプリを突合対象にできる**。
      集計アプリの編集権限は、そうしてよい担当者だけに絞ること。

## 一覧URLの貼り付け(list-url.js)

- [x] 貼り付けられたURLは`js/lib/list-url.js`の`parse()`で解析し、
      アプリIDは数字のみ、一覧IDも数字のみを通す。URL全体を`href`等に使うことはない。
- [x] 取り出したクエリ文字列はREST APIの`query`パラメーターにそのまま渡す。
      kintone側でクエリとして構文検証されるため、不正な条件はAPIエラーになるだけで、
      別アプリのデータが漏れる経路にはならない(`app`は別途数字検証済みのIDを渡している)。
- [x] `decodeURIComponent()`は不正なパーセントエンコードで例外を投げるため、
      try/catchで握って元の文字列を返す(画面が固まらないようにするため)。
- [x] `sourceUrl`(貼り付けられたURL文字列)はレコードに保存され、設定を開き直したときに
      入力欄へ復元されるが、`value`への代入のみで`href`やDOM構造には使わない。

## 設定値の検証

- [x] アプリIDは保存時に`/^[0-9]+$/`で検証する(`js/lib/definition-validation.js`の`isAppId()`)。
- [x] **集計アプリ自身を基準アプリ/対象アプリに指定できないようにしている。**
      指定できてしまうと、突合結果のレコードが母集団に混ざって結果が壊れるうえ、
      実行のたびにレコードが増殖しうるため。
- [x] 壊れた設定(不正なJSON、想定外の型)でも画面が必ず開けるよう、
      `js/lib/config-store.js`と`js/lib/definition-store.js`の読み込みは
      例外を握って既定値を返す。レコード画面側は設定が不正なら
      「突合設定が未完了です」と表示して何もしない。

## 認証情報・外部通信

- N/A — 外部サービスとの認証・APIキーのやり取りは行わない。
      `kintone.plugin.app.setConfig()`に保存するのは表記と上限件数のみ、
      レコードの`cac_definition`に保存するのはアプリID・フィールドコード・絞り込みクエリ・
      表示ラベル・貼り付けられた一覧URLのみで、いずれも認証情報や機密情報は含まない。
- [x] kintone以外のサーバーへの通信は一切行わない。外部ライブラリも組み込んでいない
      (CLAUDE.md開発方針9)。

## 個人情報の取り扱い(運用上の注意)

- [!] **突合結果のJSONファイルには、対象者の突合キー(個人番号・宛名番号等)と氏名が
      平文で含まれる。** このファイルは集計アプリのレコードに添付されるため、
      集計アプリのレコード閲覧権限を持つ人は全員が対象者一覧を参照できる。
      アプリのアクセス権を、閲覧してよい担当者だけに絞る必要がある。
      この注意は`idea.md`の「未解決・利用時の注意点」と公開ページにも記載している。
- [x] プラグイン側で外部にファイルを送信することはなく、CSVダウンロードは
      `URL.createObjectURL()`によるブラウザ内でのファイル生成のみ(サーバーを経由しない)。

## 実行タイミング・権限

- [x] 突合の実行はレコード詳細画面のボタン押下起点のみで、画面表示時の自動実行は行わない
      (意図しないAPI消費とレコード更新を防ぐため)。
- [x] 実行中はボタンを`disabled`にして二重実行を防ぐ。
- [x] 設定未完了、または集計用フィールド(スペース)が未作成のアプリでは、
      ビューワを描画せず画面をクラッシュさせない(`js/desktop.js`)。
- [x] 突合は「基準アプリ・対象アプリの**閲覧権限**」と「集計アプリの**編集権限**」の範囲で動く。
      権限のないアプリを指定してもAPIがエラーを返し、その旨が画面に表示されるだけで、
      プラグインが権限を越えて読み書きすることはない。

# 入力規則プラグイン

## 機能

文字列(1行)フィールドに対して、管理者が選んだ「禁止する文字種」がレコード保存前に混入していないかを
チェックし、含まれていればそのフィールドにエラーを表示するプラグイン。

- 設定画面でルールを複数追加できる。ルールごとに:
  - 対象フィールド(文字列1行フィールドから1つ選択)
  - 禁止する文字種(チェックボックスで複数選択、後述の10種類)
- レコード追加・編集画面で、対象フィールドの値を変更したとき(`create.change`/`edit.change`)、
  および保存時(`create.submit`/`edit.submit`)にチェックし、禁止文字が含まれていれば
  `record[フィールドコード].error`にメッセージを設定する(保存もブロックされる、後述)。
- PC・モバイル両対応(後述の「対応画面」参照)。

## 禁止できる文字種(10種類、チェックボックスで選択)

「半角/全角」×「かな/カタカナ/英数字/記号」の組み合わせのうち、実際に存在する7種類
(半角ひらがなはJIS上存在しないため対象外)に加えて、次の3種類を用意する
(初回リリース後のユーザー要望「全角すべて禁止、半角すべて禁止も追加したい」「あとスペース禁止も」
への対応)。

| チェックボックス | 対象文字の例 | Unicode範囲(実装で使用) |
| :-- | :-- | :-- |
| 全角ひらがな | あ、ぱ、ゝ | U+3041–U+3096, U+309D–U+309E |
| 全角カタカナ | ア、パ、ー(長音) | U+30A1–U+30FA, U+30FC–U+30FE |
| 半角カタカナ | ｱ、ﾊﾟ | U+FF66–U+FF9F |
| 全角英数字 | Ａ、１ | U+FF10–U+FF19, U+FF21–U+FF3A, U+FF41–U+FF5A |
| 半角英数字 | A、1 | U+0030–U+0039, U+0041–U+005A, U+0061–U+007A |
| 全角記号 | 、。「」（）＃ | U+3000–U+303F, U+FF01–U+FF0F, U+FF1A–U+FF20, U+FF3B–U+FF40, U+FF5B–U+FF60, U+FFE0–U+FFE6 |
| 半角記号 | !"#、｡｢｣･ | U+0021–U+002F, U+003A–U+0040, U+005B–U+0060, U+007B–U+007E, U+FF61–U+FF65, U+FFE8–U+FFEE |
| 全角(すべて) | 上記の全角4分類 + 漢字 | 上記4分類の範囲 + U+3400–U+4DBF(CJK統合漢字拡張A), U+4E00–U+9FFF(CJK統合漢字), U+F900–U+FAFF(CJK互換漢字) |
| 半角(すべて) | 上記の半角3分類の合併 | U+0021–U+007E(半角スペースを除く印字可能ASCII), U+FF61–U+FF9F(半角カタカナ), U+FFE8–U+FFEE(半角記号) |
| スペース | 半角スペース、全角スペース | U+0020, U+3000 |

**「全角(すべて)」は既存の4分類の単純な組み合わせではない点に注意。** 漢字(CJK統合漢字)は
全角ひらがな・全角カタカナ・全角英数字・全角記号のいずれの範囲にも含まれないため、この4つを
すべてチェックしても漢字はすり抜けてしまう。そのため「全角(すべて)」は独自に漢字の範囲を
含めた正規表現として定義している(`js/lib/char-type.js`のコメント参照)。
一方「半角(すべて)」は半角カタカナ・半角英数字・半角記号の範囲を単純に合併したものと等価
(半角に「既存の分類に含まれない文字種」は実務上存在しないため)。

「スペース」は「全角(すべて)」には既に全角スペース(U+3000)が含まれる一方、「半角(すべて)」には
半角スペース(U+0020)をあえて含めていない(印字可能文字と空白は概念的に別カテゴリとして扱うのが
一般的なため)。スペースだけを単独で禁止したい場合(例: 前後の余計な空白、単語間の全角スペース)に
使う想定。

`js/lib/char-type.js`の`RANGES`が上記の正規表現を保持し、`detectForbiddenTypes(value, forbid)`が
`forbid`(チェックボックスの選択状態)のうち実際に値に含まれる違反種別を配列で返す(純粋関数、
`__tests__/char-type.test.js`で各カテゴリの代表文字を使ってテスト済み)。

## 対象フィールド(実機・公式ドキュメントで確認済み)

`app.record.create.change.フィールドコード`/`app.record.edit.change.フィールドコード`イベントの
公式ドキュメント「フィールドコードに指定可能なフィールド」には、ラジオボタン・ドロップダウン・
チェックボックス・複数選択・ユーザー選択・組織選択・グループ選択・日付・時刻・日時・
**文字列1行**・数値・テーブル・ルックアップが列挙されており、**文字列(複数行)は含まれない**。
文字列(複数行)フィールドは値変更時に`.change`イベントが発火しないため、リアルタイムの
禁止文字チェックができない(保存時の`.submit`イベントでのみ検知可能になり、UXが変更フィールドと
異なってしまう)。禁止文字チェックの主な用途(氏名・フリガナ・電話番号・製品コード等の1行入力)にも
文字列1行で十分なため、本プラグインの対象フィールドは**文字列1行(SINGLE_LINE_TEXT)のみ**とする
(設定画面のフィールド選択もSINGLE_LINE_TEXT型のみ列挙する)。

`.change`イベントの発火タイミングは「コントロールからフォーカスが外れたとき」(公式ドキュメント)
であり、1文字入力するたびではなくフィールドからフォーカスが外れた時点でチェックされる。

## 発動する画面・タイミング(確定)

- `app.record.create.change.<フィールドコード>` / `app.record.edit.change.<フィールドコード>`:
  対象フィールドにルールが設定されている場合のみイベントを登録する(設定にないフィールドコードの
  イベントは登録しない、無駄なイベント登録を避ける)。値が変更されるたびに、そのフィールド1つ分の
  ルールだけを再チェックし、`record[フィールドコード].error`を更新(違反なしなら`null`でクリア)する。
- `app.record.create.submit` / `app.record.edit.submit`: 保存直前に全ルールをまとめて再チェックする
  (change イベントを経由しない自動計算・コピー&ペースト等の値変更も保存時に必ず捕捉するため)。
  1件でも違反があれば、公式ドキュメント「保存処理をキャンセルする」の方法の1つである
  「フィールドにエラーを表示する」により保存がブロックされる。あわせて`event.error`に
  「入力内容にエラーがあります。各項目のエラーメッセージを確認してください。」を設定し、
  画面上部にもエラーがあることを表示する(requiredConditionプラグインと同じ方針)。

## 対応画面(PC・モバイル両対応)

本プラグインが使用するAPIは`kintone.events.on()`(`record[フィールドコード].error`への代入含む)の
みで、PC専用APIを一切使用しない(設定画面での`kintone.app.getFormFields()`のみプラグイン設定画面
専用だが、これはPC/モバイルの区別と無関係)。そのため`js/desktop.js`
(`app.record.create.change.*`/`app.record.edit.change.*`/`app.record.create.submit`/
`app.record.edit.submit`)と`js/mobile.js`(同様に`mobile.`プレフィックス付きのイベント名)の
両方を用意し、ロジック本体(`js/lib/`配下)は完全に共有する(`subtable_sort`と同じ構成)。

## 設定画面

`kintone.plugin.app.setConfig()`にのみ保存する。

- ルールを追加・削除できる。ルールごとに:
  - 対象フィールド(`kintone.app.getFormFields()`で取得したSINGLE_LINE_TEXT型フィールドから選択。
    戻り値はREST APIの`properties`と同じ形の値だが`{ properties: {...} }`のようにラップされない
    ことを実装前にkintone_doc MCPで確認済み、`resp.properties`のような誤ったアクセスはしていない)
  - 禁止する文字種(7つのチェックボックス、前述)
- 保存時に`js/lib/config-validation.js`でチェックする(対象フィールド未選択、禁止文字種が
  1つも選ばれていない、同じフィールドに複数のルールが重複している、を検出して保存させない)。

## エッジケース・既知の制約

- 対象フィールドが文字列1行以外(型変更等で不整合が生じた場合)でも、`record[フィールドコード]`が
  存在しなければ何もしない(画面をクラッシュさせない)。
- 値が空文字列の場合はどの文字種も検出されない(エラーにならない)。空文字列を禁止したい場合は
  kintone標準の「必須項目」設定を別途使うことを想定し、本プラグインの対象外とする。
- 複数のルールが同じフィールドに設定されることは設定画面のバリデーションで防止する(意図が
  曖昧になるため)。
- サブテーブル内の文字列1行フィールドは対象外(`.change`イベント名にサブテーブルのフィールド
  コードを直接指定する方式がkintoneの仕様上異なる〈行データを含むイベントになる〉ため、
  本プラグインのシンプルな「フィールドコード直接指定」方式のスコープ外とする)。

## E2Eテストで実機確認した事項(推測実装ではないことの記録)

- `kintone.app.record.getFieldElement()`は**レコード詳細画面・レコード印刷画面でのみ利用可能**
  (公式ドキュメントの「利用できる画面」に追加・編集画面が含まれない)。実際に追加画面で
  呼び出すと`null`が返ることを実機で確認した。そのため、E2Eテストでフィールドの入力要素を
  直接操作する用途にはこのAPIを使わず、`kintone.app.record.set()`で値を書き換える方式にした
  (次の項目参照)。
- `kintone.app.record.set()`で値を書き換えると、公式ドキュメント「フィールドの値を変更した
  ときのイベント」に明記されている通り`.change.フィールドコード`イベントが実際に発火し、
  本プラグインのエラー表示が反映されることを実機で確認した(E2Eテストがこの方式で
  安定して動作している)。
- kintoneがフィールドエラーを表示する要素の実際のCSSクラス名は`input-error-cybozu`
  (実機で確認済み、`src/e2e/record-validation.e2e.test.js`参照)。
- 追加・編集画面の保存ボタンの実際のCSSクラス名は`gaia-ui-actionmenu-save`(実機で確認済み)。
- 保存時に禁止文字が含まれている場合、`event.record[フィールドコード].error`を設定するだけで
  URLが`/edit`のまま(`/show`へ遷移しない)保存がブロックされ、`event.error`のメッセージが
  画面上部に表示されることを実機で確認した(公式ドキュメント「保存処理をキャンセルする」の
  記載通りの挙動)。

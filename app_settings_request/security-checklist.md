# app_settings_request セキュリティチェックリスト

[secureCodingGuideline.md](../secureCodingGuideline.md)の一般項目([box_gdrive_iframe/security-checklist.md](../box_gdrive_iframe/security-checklist.md)参照。UTF-8/BOMなし・名前空間分離(`window.AppSettingsRequest`)・`'use strict'`・外部スクリプト不使用・`kintone.api()`のみ使用など)は同様に満たしているため重複記載を省略し、本プラグイン固有の項目のみ記載する。

最終確認日: 2026-10-21

## 【最重要】権限境界(他アプリの設定を変更するプラグイン)

- [x] 反映APIはすべて**完了アクションを実行したユーザーの権限**(セッション認証の`kintone.api()`)で呼ぶ。APIトークン・パスワード等の認証情報は一切保存・使用しないため、プラグインを通じて権限が昇格することはない
- [x] 反映前に`GET /k/v1/app/acl.json`(アプリ管理権限が必須のAPI)で対象アプリの管理権限を確認し、権限エラー(`CB_NO02`)なら「管理権限がありません」と表示してアクションをキャンセルする(ステータスは変わらない)。権限が無ければ後続の変更APIもkintone側で拒否される(二重の防御)
- [x] 依頼アプリ自身は対象にできない(エディタで除外し、反映時にも`apply-runner.js`で拒否。ユニットテスト済み)
- [x] 既定の承認フローでは、作業者未設定だと閲覧者全員が「承認する」を実行できてしまう(kintoneの仕様)ため、「承認待ち」の作業者を設定を保存したユーザーにして作成し、設定画面で承認経路の見直しを強く促す注意書きを表示する

## 依頼内容(JSON)の改ざん対策

- [x] 反映に使う情報は`asr_change_json`のみ。編集画面・CSV読み込み・REST APIで書き換えられ得るため、`ChangeRequest.parseChange()`で`format`/`version`、アプリID・ゲストスペースID(正の整数のみ)、フィールド情報、`operation`のホワイトリスト、`after`の型を厳密に検証し、既知のプロパティだけを取り出す(余計なプロパティはAPIへ流さない。ユニットテスト済み)
- [x] APIへ送るプロパティは`Operations.buildPropertyPatch()`が変更内容ごとに決めたものだけ(`label`/`code`/`noLabel`/`required`/`unique`/`defaultValue`/`options`/`minLength`・`maxLength`/`minValue`・`maxValue`)。計算式(`expression`)・ルックアップ・関連レコード一覧の設定など、JSONから任意のプロパティを書き込む経路はない
- [x] 反映直前に対象フィールドの現在の定義を取得し、存在・種類の一致・その変更内容が選べること・値の妥当性(選択肢に含まれる初期値、既存コードと重複しないフィールドコード等)を再検証する
- [x] JSONのアプリIDとレコードの`asr_app_id`が一致しなければ中止する(一覧で見えている対象アプリと実際の反映先の食い違いを防ぐ)
- [x] 承認者が古い画面のまま承認した場合に備え、反映直前に`GET record.json`で依頼レコードを取り直し、画面上のJSONと一致しなければ中止する
- [x] 詳細画面の依頼内容は毎回JSONから生成して表示する(表示用の別フィールドを信用しない)。承認者が見た内容=反映される内容
- [x] ゲストスペースIDは正の整数のみ受け付け(`api-path.js`の`buildApiPath`でも再検証)、任意文字列がAPIパスに混入しない

## 対象アプリへの影響範囲

- [x] 対象アプリに運用環境へ未反映の変更がある場合(運用環境と動作テスト環境の`revision`が異なる。実機確認済み)は中止し、他人の作業途中の設定をデプロイしない
- [x] 変更APIは取得時の`revision`を指定して送る(取得から変更までの間に他の変更が入ったらkintoneがエラーにする)。デプロイも変更後の`revision`を指定する
- [x] デプロイに失敗した場合は`revert: true`で動作テスト環境の変更を取り消す。取り消しにも失敗した場合は手動で「変更を中止」するよう案内する
- [x] 選択肢の名前変更はkintoneが既存レコードの値・絞り込み条件まで書き換える(実機確認済み)ため、追加・名前変更の結果が別の既存の選択肢名になる指定(入れ替え・統合)は`option-changes.js`の`validateEntries`で拒否する(ユニットテスト済み)。エディタ・詳細画面で「既存レコードの値も変わる」「削除した値は既存レコードに残る」ことを警告する
- [x] フィールド削除は確認チェックを必須にし、データが削除され元に戻せない旨をエディタ・詳細画面で警告する。グループ・テーブル(中のフィールドも消える)・システムフィールドは削除の対象外
- [x] ステータス・作業者・カテゴリー(変更・削除APIの制限事項)は選択肢に出さない

## REST APIの利用(JavaScript APIで代替不可)

- [x] 他アプリのフィールド取得・変更・削除、アクセス権取得、デプロイ、アプリ検索、プロセス管理の設定はいずれもJavaScript APIで代替できない(`kintone.app.getFormFields()`は自アプリのみ)。すべて`kintone.api()`経由で呼び出し、生の`fetch`/`XMLHttpRequest`は使わない

## XSS対策

- [x] エディタ・詳細画面の表示はすべて`document.createElement()` + `textContent`で組み立て、`innerHTML`を使わない。アプリ名・フィールド名・選択肢名・初期値など対象アプリ由来の任意文字列もすべて`textContent`で設定する
- [x] 詳細画面の対象アプリへのリンクは、検証済みのアプリID・ゲストスペースID(数字のみ)から組み立てた相対パスのみ(`javascript:`等が入り得ない)。`target="_blank"`には`rel="noopener"`を付ける
- [x] 設定画面のエラー・進捗・状態表示も`textContent`のみ。モバイルのエラーは`alert()`(プレーンテキスト)

## 依頼アプリの自動設定

- [x] フィールドは既存のフィールドコードとの差分のみ追加し(`diffMissingFields`)、既存フィールドは変更・削除しない。フィールドコードは`asr_`接頭辞で衝突を避ける
- [x] プロセス管理は、一度も設定していない場合のみ既定フローを作成する。設定済みの場合は既存のステータス・アクションを変更せず(OFFならそのままONにするだけ)、完了ステータスや完了へ進むアクションが無ければエラーにして利用者に任せる
- [x] 本プラグインの設定には認証情報を保存しない(`completeStatus`のみ)

## 一覧の作成・修正・削除

- [x] 一覧画面のURLの変換のために、同一オリジンの非表示iframeで対象アプリの一覧画面を開く。開くURLは`query-url.js`の`parseListUrl`で
  「このkintone環境(`location.origin`)の`/k/{アプリID}/`または`/k/guest/{ID}/{アプリID}/`」に限定し(別ドメイン・`javascript:`・詳細画面・管理画面は不可。ユニットテスト済み)、
  さらにアプリIDが選択中の対象アプリと一致する場合だけ開く。iframeの`src`には検証済みのパス以降だけを渡す
- [x] iframeで開いた一覧画面では、利用者が普段その一覧を開いたときと同じく、対象アプリのJavaScript・プラグインが利用者の権限で動作する
  (変換のために一覧画面を1回開くのと同等)。iframeは変換が終わったら(成功・失敗・30秒のタイムアウトとも)すぐに取り除く
- [x] iframeから読むのは公式のJavaScript API(`kintone.app.getQueryCondition()`/`getQuery()`)の戻り値(文字列)だけで、iframe内のDOMは操作しない
- [x] 変換結果はクエリ文字列として変更内容JSONに保存し、表示は`textContent`のみ。kintoneが反映時に条件の妥当性(存在しないフィールド等)を検証する
- [x] 「一覧の設定を変更するAPI」は送らなかった一覧を削除するため、反映直前に取得した全一覧を送り返し、対象の一覧(`id`で特定)だけを変える(`view-changes.js`、ユニットテスト済み)。
  変更内容JSONの一覧の値は`name`/`filterCond`/`sort`/`fields`/`sourceUrl`だけを取り出し(`type`・`html`等は捨てる。ユニットテスト済み)、作成する一覧は常に表形式
- [x] 「（作業者が自分）」・カスタマイズ形式の一覧は修正・削除できない(カスタマイズ形式のHTMLを扱わない)。ただし対象アプリにカスタマイズ形式の一覧があると、
  全一覧を送り返すAPIの性質上、変更にkintoneシステム管理権限が必要になる可能性がある(ドキュメントの必要なアクセス権。検証環境ではシステム管理者でしか確認できていない)。権限エラーはそのまま表示してキャンセルする

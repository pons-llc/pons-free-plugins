# ジェノグラム作成プラグイン

## 機能概要

- 人物・夫婦(パートナー)関係・親子関係・情緒的な関係・同居(世帯)・メモを、**1つの「文字列(複数行)」フィールドに
  構造化データ(JSON)として保存**し、レコードの**スペースフィールドにジェノグラム(家族関係図)として自動描画**する。
- 想定利用者: 福祉・介護・児童相談・保健などの相談支援記録。ケース(相談者)1件=1レコードで家族構成を記録する。
- 位置は自動で配置する(世代ごとに上から下へ。夫婦は横に並べ、子は夫婦の線の下にぶら下げる)。
  追加・編集画面では人物をドラッグして位置を微調整でき、「自動配置に戻す」で手動の位置をすべて解除できる。
- **メモ(コメント)の追記**: レコード全体または人物ごとに、日時・記入者付きのメモを追記できる。
  詳細画面からもレコードを編集画面で開かずに追記できる(追記のみ。削除は編集画面で行う)。
- 図は「画像(PNG)を保存」で書き出せる。印刷画面にも描画する。

## 表記(記号)

日本の相談支援現場で一般的なジェノグラムの表記に揃える。凡例を図の下に表示する。

| 対象 | 表記 |
| :-- | :-- |
| 男性 / 女性 / 不明・その他 | □ / ○ / ◇ |
| 本人(クライアント) | 二重線の記号 |
| 死亡 | 記号の中に× |
| 年齢 | 記号の中に表示 |
| 婚姻 | 2人の記号の下を結ぶ実線 |
| 内縁・事実婚・交際 | 破線 |
| 別居 | 実線に斜線1本(/) |
| 離婚 | 実線に斜線2本(//) |
| 実子 / 養子 / 里子 | 親の線から下ろす実線 / 破線 / 点線 |
| 情緒的関係: 親密 / 対立 / 疎遠 / 断絶 | 太線 / ジグザグ線 / 点線 / 線の中央に縦線2本 |
| 同居 | 同居している人物を囲む枠(破線)。枠の左上に世帯名 |
| メモ | メモがある人物の右上に件数バッジ |

## データ構造(JSON, version 1)

```json
{
  "version": 1,
  "persons": [
    { "id": "p1", "name": "山田太郎", "gender": "male", "age": "45", "deceased": false, "isClient": true,
      "note": "会社員", "parentUnionId": "u0", "parentId": "", "childType": "biological", "pos": { "x": 120, "y": 40 } }
  ],
  "unions": [{ "id": "u1", "a": "p1", "b": "p2", "status": "married", "note": "" }],
  "relations": [{ "id": "r1", "a": "p1", "b": "p3", "kind": "conflict", "note": "" }],
  "households": [{ "id": "h1", "label": "同居", "members": ["p1", "p2"] }],
  "memos": [{ "id": "m1", "targetId": "p1", "text": "…", "author": { "code": "sato", "name": "佐藤" }, "at": "2026-10-20T01:23:45.000Z" }]
}
```

- `gender`: `male` / `female` / `unknown`。`status`: `married` / `cohabiting` / `separated` / `divorced`。
  `kind`: `close` / `conflict` / `distant` / `cutoff`。`childType`: `biological` / `adopted` / `foster`。
- 親子関係は子の側に持つ。両親が分かる場合は`parentUnionId`(夫婦のID)、片親のみの場合は`parentId`(人物ID)。
  1人につき親の組は1つ(実親と養親の両方を同時に表す、は対象外)。
- `pos`は手動で動かしたときだけ持つ(無ければ自動配置)。`memos[].targetId`が空ならレコード全体へのメモ。
- 兄弟の並び順は`persons`配列の順(=追加した順)。人物の編集フォームで「左へ/右へ」で入れ替えられる。
- 読み込み時に正規化する(`js/lib/model.js`): 壊れた参照(存在しない人物を指す夫婦・関係・親)・自分自身との
  夫婦・重複IDは捨て、未知の値は既定値にし、文字列は長さを制限する。**JSONとして読めない値**は、編集画面で
  上書きして消してしまわないよう、エラーを表示してエディターを出さない(フィールドを表示して手で直してもらう)。

## 自動配置(`js/lib/layout.js`)

1. 世代: 子は親より1つ下(`子 ≥ 親+1`)、夫婦は同じ世代、親は子の1つ上まで引き下げる、を収束するまで繰り返す
   (循環した入力でも回数上限で止める)。
2. 並び: 同じ世代で夫婦の線でつながる人を「横並びの組」にまとめる(複数の相手がいる人は真ん中に置き、
   相手を左右交互に置く)。上の世代から順に、組を「親の位置の平均」の順に並べる(兄弟は配列順)。
3. 横位置: 各組の希望位置(上→下の段では親の真下、下→上の段では子の中心の真上)を、重ならない範囲で
   最小二乗的に近づける(1次元の「重なったら合体して平均位置に置く」方式)。上→下 → 下→上 の2段階。
4. 手動位置`pos`がある人物はその位置を使う。

## 設定画面

- **データを保存するフィールド**(文字列(複数行)、テーブル外)を選ぶ。必須。
- **図を表示するスペースフィールド**(テーブル外。グループ内は可)を選ぶ。必須。
- 「データ(JSON)のフィールドを画面に表示しない」(既定ON)。
- いずれかの候補がフォームに無い場合は、フォームに追加するよう警告を出す。

## 画面ごとの挙動

- **追加・編集画面(PC)**: 図 + エディター。
  - ツールバー: 人物を追加 / 夫婦・パートナーを追加 / 関係を追加 / 同居(世帯)を追加 / 自動配置に戻す / 縮小表示 / 画像を保存。
  - 図の人物をクリック → 人物フォーム(名前・性別・年齢・死亡・本人・親・続柄・備考、左へ/右へ、削除)と、
    クイック操作「配偶者・パートナーを追加」「子を追加」「両親を追加」。夫婦・関係・世帯は一覧の「編集」から編集する。
  - 人物をドラッグして位置を調整できる(10px単位)。
  - **Ctrl(Macは⌘)またはShiftを押しながらクリックで複数人を選択**でき、選択中の誰かをドラッグすると全員を同じ
    移動量でまとめて動かす(相対位置を保つため、各人の座標ではなく移動量を10px単位に丸める。左上にはみ出す場合は
    端の人が余白で止まるよう全員の移動量を抑える)。複数選択中のパネルから「選択した人で同居(世帯)を作る」
    「位置を自動に戻す」「選択を解除」ができる。選択中の人をCtrl/Shift+クリックすると選択から外れる。
  - 変更は画面内のモデルに反映し、**保存時(`create.submit`/`edit.submit`)に`event.record`へJSONを書き込む**
    (`kintone.app.record.set()`はイベントハンドラー内で使えないため、保存イベントで返す方式に統一)。
  - 人物を削除すると、その人を含む夫婦・関係・世帯の所属・親の参照・その人へのメモを一緒に削除する(確認あり)。
    夫婦を削除すると、その夫婦の子は親未設定になる。
- **詳細画面(PC)**: 図(閲覧のみ)・凡例・メモ一覧・メモ追記フォーム・画像を保存。
  - メモの追記は`PUT /k/v1/record.json`でJSONフィールドだけを更新する。画面表示時の`$revision`を指定し、
    他の利用者が先に更新していた(`GAIA_CO02`)場合のみ最新を`GET`してメモを足し直して再度`PUT`する(最大1回)。
    成功後は画面を再読み込みする。
- **印刷画面**: 図・凡例・メモ一覧を表示。
- **一覧のインライン編集**: JSONフィールドを編集不可にする(手入力で壊さないため)。
- **モバイル**: 詳細・追加・編集画面に図(閲覧のみ)とメモ一覧を表示する。編集はPCで行う(追加・編集画面では
  値に触れないため、PCで作ったデータはそのまま保持される)。

## API実行数

- 図の表示・編集・保存はREST APIを使わない(保存はkintone標準の保存)。
- 詳細画面でのメモの追記のみ、通常1回(`PUT`)、他の利用者と更新が競合したときだけ計3回(`PUT`→`GET`→`PUT`)。

## エッジケース

- JSONフィールドが空 → 空の図(「人物を追加」から始める案内)。
- 循環した親子関係(手で書き換えたJSON等) → 世代計算は上限回数で打ち切り、描画はする。
- 人物0人で保存 → 空文字ではなく空のJSON(`persons: []`)を保存する。
- JSONの文字数が多い場合: 文字列(複数行)の上限を超えると保存時にkintoneがエラーにする(人物数百人規模で到達。
  通常のケース記録では問題にならない)。

## オフライン版(kintoneを使っていない人向け)

- kintoneが無い・インターネットに接続できない環境でも使えるよう、**1つのHTMLファイル**(`webapp/dist/genogram-offline.html`)
  として配布する。ダウンロードしてダブルクリックするとブラウザで開き、インストール・ネット接続は不要。
- kintone版と同じコード(`src/js/lib/*`・`renderer.js`・`viewer.js`・`editor.js`・`css/desktop.css`)を
  `webapp/build.js` で埋め込む(外部パッケージ不使用)。kintone依存の `desktop.js` の代わりに `webapp/app.js` が画面を作る。
  エディターの機能(自動配置・ドラッグ・複数選択・メモ・画像の保存)はkintone版と同じ。
- **データはケースファイル(.json)で保存・読み込み**する(`src/js/lib/case-file.js`)。ケース名・保存日時とジェノグラムのデータ
  (kintone版のフィールドの値と同じ形)を1つにまとめる。kintone版のフィールドの値(JSON)もそのまま開ける。
  ファイル名は「ケース名_YYYYMMDD.json」(ファイル名に使えない文字は `_`)。
- 「ファイルを開く」・ドラッグ&ドロップで開く。「保存する」(Ctrl/⌘+S)でダウンロード。保存していない変更がある状態で
  新規・開く・閉じる場合は確認する。
- **ブラウザのストレージ(localStorage等)には何も保存しない**。共用パソコンに個人情報を残さないため(閉じる前に保存が必要)。
- **外部への通信を一切させない**: HTMLのContent-Security-Policyで `default-src 'none'`(スクリプト・スタイルは埋め込みのみ、
  画像は data:/blob: のみ)とし、仕組みとしてデータが外に出ないようにする。
- 記入者名は画面上部の入力欄の値をメモに記録する(kintone版のログインユーザーの代わり)。
- 印刷: ヘッダー・編集パネル等を隠し、ケース名・図・凡例・メモを印刷する(印刷の間だけ凡例を開く)。
- テスト: `src/__tests__/case-file.test.js`(ケースファイル)、`src/e2e/webapp-offline.e2e.test.js`(file://で開いて、
  外部リクエストが0件・保存→開くの往復・未保存の確認・不正なファイル・kintone版のJSON・画像の保存・印刷用の表示)。
- ビルド: `node genogram/webapp/build.js`

詳細カレンダープラグイン

レコード一覧画面(表形式)に、日付/日時フィールドを軸にした週表示・日表示のカレンダーを表示するプラグインです。 グループ分けフィールドを指定して担当者・組織・ステータスなどの列(または行)に分けて表示でき、 縦/横のデザインを選べます。イベントをクリックするとレコード詳細画面へ遷移し、ドラッグ&ドロップで 日時を変更することもできます(設定で有効化した場合)。レコードの取得にREST APIを一切使わず JavaScript APIのみで実現しているため、表示できるのは一覧の現在ページから最大100件までです (この制限はカレンダーのヘッダーに常時表示されます)。

ユースケース

グループ分けフィールドに担当者(ユーザー選択)を指定すると、日表示で担当者ごとの列(または行)に予定が並びます。誰が何時にどの予定を持っているかを一目で確認できます。

週表示に切り替えると、日曜〜土曜の7日分の予定がグループごとに色分けされたチップとして並びます。今週・来週の予定の偏りを俯瞰したい場合に便利です。

設定でドラッグ&ドロップ編集を有効にすると、イベントを別の時間帯・別のグループへドラッグするだけで、開始/終了日時(グループ分けフィールドが対応型の場合はその値も)を更新できます。予定の微調整をレコード詳細画面を開かずに行えます。

セットアップ手順

  1. プラグインをアプリに追加し、設定画面を開く。
  2. 対象一覧のIDを入力して「+ この一覧の設定を追加」を押す(空欄のままなら、ビルトインの「すべて(デフォルト)」一覧向けの設定になる)。対象の一覧を開いたときのブラウザURLに含まれるview=の数字が一覧IDです。
  3. タイトルフィールド(必須)・開始日時フィールド(必須)・終了日時フィールド(任意)・グループ分けフィールド(任意)・ホバー項目(任意、複数選択可)を選ぶ。
  4. 既定の表示単位(週/日)・デザイン(縦/横)を選び、必要であればドラッグ&ドロップ編集を有効化する。
  5. 保存後、アプリを更新する(kintoneのアプリ設定は保存しただけでは反映されず、更新〈デプロイ〉して初めてレコード一覧画面に反映されます)。

対象は通常の一覧(表形式)・PC画面のみです。カレンダーは一覧本体(表)の上にあわせて表示され、一覧本体自体は非表示になりません。表示できるレコードは一覧の現在ページから最大100件までで、この制限はカレンダーのヘッダーに常時表示されます。100件を超える一覧では、kintone側の一覧設定(絞り込み条件・ページ件数)を調整してください。

セキュリティレビュー結果サマリ

kintoneセキュアコーディングガイドラインに沿って実装時にチェックしています。特に重要な点は次のとおりです。

  • レコードの取得にはREST APIを一切使用していません。app.record.index.showイベントのevent.records(JavaScript APIの一部)のみを使い、対象一覧の指定もREST APIでの一覧列挙を避け一覧IDの直接入力方式にしています。
  • 唯一のREST API利用は、ドラッグ&ドロップでの日時変更(PUT /k/v1/record.json、kintone.api()経由)のみです。任意のレコードを更新するJavaScript APIが存在しないための例外的な利用で、既定では無効になっています。更新時はレコードのリビジョン番号を指定し、他ユーザーとの同時編集による競合を検出します。
  • イベントのタイトル・ホバー項目・グループラベルなど、レコード値に由来する文字列はすべてtextContentへの代入、またはツールチップ用のtitleプロパティ代入で挿入しており、innerHTMLは一切使用していません。
  • 色分けに使う値は固定パレットのインデックス選択にのみ使用し、CSSやHTMLへ値そのものを埋め込むことはありません。
  • 外部サーバーへの通信・外部ライブラリの利用は一切ありません。

API実行数について

このプラグインは、レコードの取得にはREST APIを使いません(app.record.index.showイベントのevent.recordsのみ)。唯一のREST API実行は、ドラッグ&ドロップでイベントを移動したときのPUT /k/v1/record.json(1件更新)で、ドラッグ操作のたびに1回だけ実行されます。ドラッグ&ドロップを有効化していない場合、このプラグインはREST APIを一切実行しません。

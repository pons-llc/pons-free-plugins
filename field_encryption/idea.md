# フィールド暗号化プラグイン

## 機能概要

文字列(1行)・文字列(複数行)フィールドの値を、レコード保存時にブラウザ内(Web Crypto API)で
AES-256-GCM暗号化してから保存する。kintoneのREST APIは保存されている生の値をそのまま返すため、
画面上の表示を隠すだけの「マスキング」ではAPI越しに値が読めてしまう。本プラグインは値そのものを
暗号文に変換して保存することで、REST API・画面キャプチャのいずれからも平文を読み取れない状態にする。

暗号化の鍵は、レコードごとに1つのパスフレーズから導出する。パスフレーズはプラグイン設定・
localStorage・Cookie・kintoneのいずれのフィールドにも保存しない(`secureCodingGuideline.md`の
「認証情報の保存先」で非推奨とされる保存先を一切使わない)。ユーザーは詳細画面・編集画面を開くたびに
パスフレーズを入力して復号する必要がある。

**パスフレーズを紛失した場合、暗号化されたデータは復号する手段がなく永久に読めなくなる。** これは
バグではなく設計上の trade-off であり、設定画面・本ドキュメントの双方に警告文として明記する。

## v1のスコープ(確定)

- 対象フィールドタイプ: 文字列(1行) `SINGLE_LINE_TEXT` / 文字列(複数行) `MULTI_LINE_TEXT` のみ。
- PC・モバイルの両方に対応する(モバイル対応の詳細は後述)。
- 印刷画面はマスク表示のみ対応(復号ボタンは置かない。印刷物に暗号文の生データをそのまま出さない
  ための最低限の対応)。印刷画面はPCのみに存在し、モバイルには印刷画面のカスタマイズ対象イベント
  自体が無いため対応不要。

## パスフレーズの運用(確定、ユーザーとの対話で確定した仕様)

- 1レコードにつきパスフレーズは1つ。対象フィールドが複数あっても、共通のパスフレーズで一括暗号化・
  一括復号する(フィールドごとに別のパスフレーズを持たせない)。
- 暗号化は**レコード保存(submit)時に自動実行**する。手動の「暗号化する」ボタンは設けない。
  対象フィールドがすべて空の場合はパスフレーズ入力を要求せず、何もしない(保護すべき値が無いため)。
- **v1では「パスフレーズを変更する」フローを設けない。** 新規作成時に設定したパスフレーズが、その
  レコードの唯一の正しいパスフレーズになる。編集画面で正しいパスフレーズにより復号できたら、保存時に
  同じパスフレーズで自動的に再暗号化する(新しいsalt/IVを使うが、パスフレーズ自体は変わらない)。
- 復号は詳細画面・編集画面の両方で、スペースフィールドに設置した「復号」ボタン押下 → パスワード欄
  (`type="password"`のネイティブ`<input>`。ブラウザのパスワードマネージャーによる自動入力に対応させる
  ため`autocomplete="current-password"`/新規作成時は`autocomplete="new-password"`を指定)への入力、
  という流れで行う。1回の入力で、対象フィールドすべてを一括で復号する。

## 保存フォーマット

各フィールドの値には、以下をJSON化してbase64エンコードし、バージョン識別用の接頭辞`FE1:`を付けた
文字列を保存する。

```
FE1:<base64({v:1, kdf:"PBKDF2-SHA256", iter:600000, cipher:"AES-256-GCM", salt:<base64>, iv:<base64>, ct:<base64>})>
```

- 鍵導出: PBKDF2-HMAC-SHA256、600,000回反復(OWASP Password Storage Cheat Sheetの2023年改訂後の
  推奨値)。導出した鍵は`extractable:false`で生成し、生の鍵データを取り出せないようにする。
- 暗号化: AES-256-GCM。IV(12byte)は暗号化のたびに新しい乱数を生成する(同一鍵でのIV使い回しは
  破滅的な弱点になるため厳禁)。
- salt(16byte)は暗号化のたびに新しい乱数を生成する。同じレコード内の複数フィールドを同時に
  暗号化する場合でも、フィールドごとに独立したsalt/IVを持たせ、各フィールドの暗号文だけで自己完結
  して復号できるようにする(他フィールドの暗号文に依存しない)。
- 正しいパスフレーズかどうかの判定は、AES-GCMの認証タグの検証失敗をそのまま利用する(専用の
  検証用ハッシュを別途保存しない)。

## 画面ごとの挙動(kintoneドキュメントMCPで確認済みのAPI制約に基づく)

実装前にkintoneドキュメントMCPで以下を確認した(推測で実装しない、CLAUDE.md開発方針1)。

- `kintone.app.record.getFieldElement(fieldCode)`は**詳細画面・印刷画面(PC)でのみ**利用可能。
  編集・追加画面では使えない(nullになる/未定義動作)。
- `app.record.detail.show`イベントは、イベントオブジェクトでの値の書き換えに対応していない
  (Promise対応のみが記載されている)。詳細画面での表示マスクは、`getFieldElement()`で取得した
  要素への直接DOM操作(`textContent`の書き換えのみ。`innerHTML`は使わない)で行う。
- `app.record.edit.show`/`create.show`は「フィールドの値を書き換える」「フィールドの編集可否を
  設定する」の両方に対応している。編集・追加画面のマスク/アンマスクは`event.record[code].value`と
  `event.record[code].disabled`の書き換えで行う。
- `kintone.app.record.getSpaceElement(id)`はPC詳細/追加/編集/印刷画面のすべてで利用できる、
  唯一一貫して使える要素追加APIのため、復号ボタン・パスワード入力欄の設置場所として使う
  (`org_lookup/src/js/desktop.js`のスペースフィールド利用パターンを踏襲)。

### 新規作成画面

`create.show`でスペース要素にパスフレーズ設定フォーム(パスフレーズ・確認用パスフレーズの2つの
`type="password"`入力欄)を表示する。対象フィールドは通常通り平文で入力できる。

`create.submit`で、対象フィールドに値があるものだけ、入力されたパスフレーズ(確認用と一致している
こと)で暗号化して保存する。対象フィールドがすべて空ならパスフレーズ未入力のままでも保存できる。

### 編集画面

`edit.show`で、各対象フィールドの現在値をメモリ上のセッション状態に退避したうえで、暗号化済みの
フィールドは「🔒 暗号化されています」のプレースホルダーに書き換えて`disabled:true`にし、復号
フォームを表示する。まだ平文の対象フィールド(過去にこのプラグインの対象に加わったばかりのフィールド
など)は通常通り編集可能にする。

`edit.submit`で、フィールドごとに以下のいずれかを行う。

- このセッションで復号しなかったフィールド → 退避しておいた元の暗号文をそのまま復元する
  (これを行わないと、プレースホルダー文字列がそのまま保存されてデータが失われる。最も重要な防御
  ロジック)。
- このセッションで復号し、値を変更した可能性があるフィールド → 復号に使ったのと同じパスフレーズで、
  新しいsalt/IVを使って再暗号化する。

### 詳細画面・印刷画面

`detail.show`/`print.show`で、暗号化済みの対象フィールドを`getFieldElement()`経由で
「🔒 暗号化されています」に書き換える(`textContent`のみ、静的な文字列を1回書き込むだけで、以後
このAPIで取得した要素へは触れない)。詳細画面のみ復号フォームを追加し、正しいパスフレーズが入力
されたら、復号結果はフィールド自体ではなくスペース要素側の表示エリアに出す(実フィールドのDOM構造を
2度書き換えない設計にすることで、kintoneガイドラインの「取得した要素の内部構造を変更しない」を
機械的に守れるようにしている)。

## モバイル対応(確定、ユーザー指示「暗号入力にはボトムシートを使う」に基づく)

実装前にkintoneドキュメントMCPで以下を確認した。

- `kintone.mobile.app.record.getFieldElement()`は**モバイルの詳細画面でのみ**利用可能(PCの
  「詳細・印刷画面のみ」と同様の制約。編集・追加画面では使えない)。
- `kintone.mobile.app.record.getSpaceElement()`はモバイルの詳細/追加/編集画面で利用できる
  (印刷画面はモバイルに存在しないため対象外)。
- モバイルには印刷画面のカスタマイズ対象イベント自体が存在しない。
- `kintone.mobile.showConfirmBottomSheet()`という公式APIが存在するが、これは
  タイトル・本文・OK/キャンセル/閉じるボタンのみを持つ**確認専用**のボトムシートで、
  テキスト入力欄を組み込むことができない。パスフレーズの入力にはテキスト入力が必須なため、
  このAPIをそのまま使うことはできない。

そのため、パスフレーズの入力手段としてボトムシート「風」のUIを自前で実装した
(`js/ui.js`の`openBottomSheet()`)。`document.body`直下に、背景を暗くするオーバーレイと、
画面下から迫り上がる`type="password"`入力欄付きのパネルを構築する(公式のボトムシートに
デザインを似せているが、内部的には独自実装)。スペースフィールドには入力欄を直接置かず、
「🔐 パスフレーズを設定」「🔓 復号する」のようなトリガーボタンのみを設置し、タップすると
ボトムシートが開く。

- 新規作成画面: トリガーボタンをタップするとパスフレーズ設定用ボトムシート(パスフレーズ・
  確認用の2つの入力欄)が開く。バリデーションに成功するとシートを閉じ、ボタンのラベルを
  「✅ パスフレーズを設定済み」に変える。入力されたパスフレーズは、画面を開いてから保存する
  までの間だけJSのクロージャ変数に保持し(PCの「フォームが保存まで残る」のと同じ理由でここでも
  永続化しない)、`create.submit`でPC版と同じロジックにより暗号化する。
- 編集画面: 暗号化済みフィールドがある場合は「🔓 復号する」ボタン→復号用ボトムシート
  (パスフレーズ1つ)、まだ無い場合は「🔐 パスフレーズを設定」ボタン→設定用ボトムシートを表示する
  (PCの「復号フォーム/設定フォームのどちらを出すか」の分岐と同じ)。ボトムシートの`onSubmit`は
  `{ success: boolean, message?: string }`を返す契約にし、失敗時(誤ったパスフレーズ等)は
  シートを開いたまま入力欄をクリアしてエラーメッセージを表示し、その場で再入力できるようにする
  (シートを閉じて再度開き直す必要がない)。成功時に呼ばれるロジックの中で、`js/lib/session-store.js`
  の`markDecrypted()`(復号成功時)または`setPassphrase()`(新規パスフレーズ設定時、v1で新設)を
  呼び、以後`edit.submit`は`getSharedPassphrase()`から一律にパスフレーズを取得できるようにした。
  PC版の`edit.submit`は「復号フォーム由来か設定フォーム由来か」で読み取り先を分岐しているが、
  モバイル版はボトムシートの成功コールバックが必ずセッションへパスフレーズを書き込むため、
  分岐が不要になっている。
- 詳細画面: `getFieldElement()`でマスク表示するのはPCと同じ。復号もトリガーボタン→ボトムシートで
  行い、復号結果自体はPCと同じくスペース要素側の表示エリアに出す(ボトムシートは入力手段としてのみ
  使い、結果表示はしない)。

パスフレーズの取り扱いに関する方針(どこにも保存しない・処理後は入力欄をDOMから消す等)は
PC版と完全に同じ。ボトムシートを閉じる際は、成功・失敗を問わず入力欄の値をクリアしてから
DOMごと除去する。

## 設定画面

`kintone.plugin.app.setConfig()`にのみ保存する(パスフレーズ自体は一切保存しない)。

- 暗号化対象フィールド(`kintone.app.getFormFields()`をSINGLE_LINE_TEXT/MULTI_LINE_TEXTで絞り込んだ
  チェックボックス。1件以上必須)
- 復号ボタンを設置するスペースフィールド(`kintone.app.getFormLayout()`を再帰的に走査してSPACERの
  `elementId`一覧から選択。必須)
- パスフレーズの最小文字数(数値、既定8文字)
- 常時表示の警告文:「パスフレーズはどこにも保存されません。パスフレーズを紛失した場合、暗号化された
  データは永久に復号できません。」

## TDD

`src/js/lib/`配下の純粋ロジックをJestでテストする(`pnpm test`)。

- `blob-codec.js` — 保存フォーマットのエンコード/デコード、暗号化済みかどうかの判定
- `crypto-codec.js` — `crypto.subtle`をDIで受け取るPBKDF2鍵導出とAES-GCM暗号化/復号
- `passphrase-validator.js` — 最小文字数・確認用入力の一致チェック
- `field-selection.js` — `getFormFields()`の戻り値からSINGLE_LINE_TEXT/MULTI_LINE_TEXTを抽出
- `session-store.js` — 編集画面の「復号しなかったフィールドは復元」「復号したフィールドは
  再暗号化」の判定ロジック(編集時の最重要ロジックのため、これを関数分離してテストする)。
  `setPassphrase()`は復号を経由せずにパスフレーズをセッションへ設定する(モバイルの設定用
  ボトムシート、および将来PC側で同様の一本化をする場合に使う、上記「モバイル対応」参照)
- `config-store.js` — 設定の読み書きとデフォルト値

kintone依存のグルーコード(`desktop.js`/`mobile.js`/`ui.js`/`config.js`)は`src/e2e/*.e2e.test.js`
(Puppeteer、`pnpm run test:e2e`)で実環境テストする。セキュリティレビューは`security-checklist.md`
参照。

# 予算管理プラグイン(budget_meter)

## 機能概要

- アプリの「一覧」(views、一覧タブ)ごとに、予算(数値)と集計対象フィールド(数値)を設定できる。
  同じ一覧に複数の予算設定行を割り当てることも可能(例: 「経費」一覧に対して費目Aの予算と費目Bの予算を別々に設定)。
- 予算が設定されている一覧を表示すると、一覧画面のヘッダーメニュー右側に「予算を確認」ボタンが表示される。
- ボタンをクリックすると、**今まさにその一覧画面に表示されている絞り込み条件**(一覧に保存された条件に加え、
  ユーザーが画面上で追加・変更した絞り込みも含む)に該当する全レコードを対象に、設定した集計対象フィールドの
  合計値を計算し、予算に対する使用率をメーター(進捗バー)としてダイアログに表示する。
- 警告しきい値・危険しきい値(%、行ごとに設定可能。デフォルト80%/100%)を境にメーターの色が
  緑→黄→赤に変わる(色だけに依存せず、パーセンテージの数値も必ず併記する)。
- これとは別に、**設定されている全ての予算をまとめて1つのダイアログで確認できる「すべての予算を確認」
  ボタン**を、許可されたグループ(ロール)に所属するユーザーにのみ一覧画面のヘッダーに表示する
  (詳細は「全予算一括表示ボタン(グループ制限)」参照)。

## 対象範囲の制限(確定事項)

- 対象となる一覧は**表形式(LIST)の一覧のみ**。カレンダー形式・カスタマイズ形式の一覧は設定画面の
  選択肢にも出さない。
  - 理由: カスタマイズ形式は一覧のHTML自体が管理者の自由記述であり、`kintone.app.getHeaderMenuSpaceElement()`
    でのボタン設置やイベント発火の前提が保証しづらい。カレンダー形式は「一覧の条件に該当する全レコード」という
    概念は成立するが、通常表を前提としたUIとの相性を優先し、まずはLIST限定でリリースする
    (将来的にCALENDARへ拡張する余地はある)。
- モバイル版は対象外(理由は下記API調査の`kintone.createDialog()`の項を参照)。

## API仕様確認(kintone_doc MCP、確認日: 2026-08-13)

- **`kintone.app.getQueryCondition()`**
  (`/en/docs/kintone/js-api/app/get-record-list-query/`、JS API、一覧画面・グラフ画面で利用可):
  一覧画面で**現在有効な**絞り込み条件をクエリ文字列で返す(フィルター条件のみ。order by/limit/offsetは
  含まれない)。一覧に保存された`filterCond`に加え、画面上のUIで追加・変更した絞り込みも反映される。
  絞り込みが無い場合は空文字列、利用できないページではnullを返す。**本プラグインの「その一覧の条件」は
  このAPIの返り値をそのまま使う**(=保存済みfilterCondだけでなく、その場でユーザーが変更した絞り込みも
  含めて集計する、という仕様)。
- **`kintone.app.getView()`**(`/en/docs/kintone/js-api/app/get-record-list-view/`、JS API、Promise):
  現在表示中の一覧の設定(`filterCond`/`sort`含む)を返すが、**アプリ設定に保存された値のままで、
  UI上の絞り込み変更を反映しない**。かつ現在表示中の一覧のみが対象で、全一覧の一覧設定は取得できない。
  → 本プラグインでは使わない(`getQueryCondition()`で足りるため)。
- **全一覧の一覧設定(id/name/type)を取得するJS APIは存在しない。** 設定画面で「対象一覧を選ぶ
  ドロップダウン」を作るには REST API `GET /k/v1/preview/app/views.json` を`kintone.api()`で呼ぶ
  (config画面は常に動作テスト環境=preview設定を編集する対象のため`preview`パスを使う。
  CLAUDE.md方針3「JS APIで代替できない場合のみREST」に合致する例外)。レスポンスの`views.一覧名.id`は
  文字列で返る。
- **`app.record.index.show`イベント**(`/ja/kintone/docs/js-api/events/idx/index-show-event/`):
  `event.viewId`(数値)・`event.viewName`・`event.viewType`(`'list'`/`'calendar'`/`'custom'`)を取得できる。
  REST `views.json`の`id`は文字列で返るため、突合せは`String(event.viewId) === row.viewId`のように
  文字列比較で行う(`js/lib/view-matcher.js`参照)。
- **`kintone.app.getHeaderMenuSpaceElement()`**
  (`/ja/kintone/docs/js-api/app/get-record-list-header-menu-element/`): 一覧画面のメニュー右側
  (集計アイコンの右側)の要素を返す。一覧画面専用。
- **`kintone.createDialog(config)`**(`/ja/kintone/docs/js-api/kintone/create-dialog/`): 任意のDOM要素を
  `config.body`に指定できるダイアログを作成できる(**PC専用**。モバイルはボトムシートAPIが別途必要で
  未対応とする)。ドキュメントに明記の通り、`config.body`に渡したElementは**そのままダイアログ本文に
  組み込まれる**ため、動的な値(合計額・一覧名など)は`textContent`で設定し、`innerHTML`に外部由来の
  文字列を直接連結しない(secureCodingGuideline.md XSS対策)。
  - **既知の落とし穴(実際に発生した不具合、CLAUDE.md既知の落とし穴にも転記済み): 戻り値の`show`関数が
    返すPromiseは、ダイアログが「表示された」時点ではなく「閉じられた」時点で解決される。**
    集計処理全体(REST呼び出し→`kintone.createDialog()`→`dialog.show()`)を1つの
    `kintone.showLoading('VISIBLE')`/`'HIDDEN'`の`try/finally`で囲むと、`showLoading('HIDDEN')`が
    ダイアログを閉じるまで呼ばれず、ローディングのオーバーレイがダイアログの上に表示されたままに
    なる。オーバーレイに遮られてユーザーがダイアログを閉じられず、ローディングが永久に消えなくなる
    (デッドロック)。対策として、`js/desktop.js`では「集計中(データを揃えるまで)」と
    「ダイアログの表示(ユーザーが閉じるまで)」を`buildDialogData()`/`showDialog()`に分離し、
    `showLoading('HIDDEN')`は前者が終わった時点(ダイアログを作る前)で呼ぶようにした。
- 自アプリのレコードを「クエリ条件に該当する全件」の単位で集計するJS APIは存在しないため、
  `GET /k/v1/records.json`をREST(`kintone.api()`)で使う。書き込みは行わない(読み取り専用の集計)ため、
  `related_record_summary`の一括集計のような**レコードカーソルAPI(対象固定用)は不要**で、
  同プラグインの「通常の全件取得方針」である**`$id`昇順ページング(500件ずつ)**をそのまま踏襲する
  (`js/lib/paged-fetch.js`、`related_record_summary/src/js/lib/paged-fetch.js`から流用)。
- **`kintone.user.getGroups()`**(`/ja/kintone/docs/js-api/kintone/get-groups/`、JS API):
  ログインユーザーの所属グループ(`{id, code, name}`の配列)を返す。画面遷移までキャッシュされ、
  1ユーザーあたり1分50回超の呼び出しでPromiseがrejectされる。「すべての予算を確認」ボタンの
  表示可否判定に使う(`related_record_summary`の一括集計ボタンと同じ方式)。
- **一覧の設定を取得するREST API には運用環境版とプレビュー(動作テスト環境)版の2つがあり、
  必要な権限が異なる**(`GET /k/v1/app/views.json`(運用環境)は「レコード閲覧権限」または
  「レコード追加権限」で足りるのに対し、`GET /k/v1/preview/app/views.json`(動作テスト環境)は
  「アプリ管理権限」が必要)。設定画面(管理者のみが開く)は編集対象である`preview`を使うが、
  「すべての予算を確認」ボタンは一般利用者(アプリ管理権限を持たない)が一覧画面で押すため、
  **運用環境版(`GET /k/v1/app/views.json`、preview無し)を使う**(`js/desktop.js`の
  `fetchProductionViewFilterConds`)。設定画面の`GET /k/v1/preview/app/views.json`呼び出し
  (`js/config.js`)とは別物であることに注意。

## 集計方法

- 合計(SUM)のみを扱う(件数・平均は本プラグインのスコープ外。「予算 vs 実績合計」がユースケースの中心のため)。
- `js/lib/aggregator.js`の`sum()`は`related_record_summary`と同じ実装を踏襲: NUMBERフィールドの値は
  文字列で返るため`Number()`変換し、空文字列・数値変換できない値は合計から除外する(0扱いにはしない=無視)。
- 集計対象フィールドの候補は、NUMBERフィールドに加えて表示書式が数値(`NUMBER`/`NUMBER_DIGIT`)のCALC
  (計算)フィールドも含める(`js/lib/aggregatable-fields.js`、`related_record_summary`と同一ロジックを流用。
  日時/時刻書式のCALCフィールドはREST値が`"49:30"`のような非数値文字列になり`Number()`がNaNになるため除外)。

## 設定画面

行(複数追加可能)ごとに以下を設定する。

| 項目 | 説明 |
| :-- | :-- |
| 対象の一覧 | REST `views.json`から取得した**LIST型のみ**のドロップダウン(表示名は一覧名) |
| 集計対象フィールド | 自アプリのNUMBER/数値書式CALCフィールドのドロップダウン |
| 予算額 | 数値。0より大きい値が必須(0除算・無意味な100%表示を防ぐため保存時にブロック) |
| 警告しきい値(%) | デフォルト80。0以上の数値 |
| 危険しきい値(%) | デフォルト100。警告しきい値以上の数値(100%超も許容=予算超過アラート用) |
| ラベル(任意) | メーターの見出し。未入力時は集計対象フィールドのラベルを使う |

バリデーション(`js/lib/row-validator.js`、TDD対象): 一覧・集計対象フィールド未選択、予算<=0、
しきい値が数値でない、警告しきい値>危険しきい値、のいずれかに該当する行があれば保存をブロックし、
具体的な行番号とエラー内容をalertで示す。

設定画面には、上記の行テーブルとは別に以下の1項目がある。

| 項目 | 説明 |
| :-- | :-- |
| 「すべての予算を確認」を許可するグループコード | カンマ区切りで複数指定可(`related_record_summary`の
  一括集計許可グループと同じ入力形式)。未入力(空)の場合はボタン自体を誰にも表示しない
  (`related_record_summary`と同様、「空 = 全員許可」ではなく「空 = 誰も許可しない」という
  安全側のデフォルトにする)。 |

## 全予算一括表示ボタン(グループ制限)

- 一覧画面のヘッダーに、通常の「予算を確認」ボタンとは別に「すべての予算を確認」ボタンを表示する。
  このボタンは**現在表示中の一覧に関わらず**(その一覧に予算設定が無くても)、
  設定が1件以上あり、かつ実行ユーザーが許可グループに所属していれば表示される。
- クリックすると、設定されている**全ての予算設定行**について、行ごとに割り当てられた一覧の
  **保存済みfilterCond**(=一覧自体の絞り込み条件。現在表示中の画面のライブな絞り込みではない。
  「API仕様確認」参照)に該当するレコードを対象に合計を計算し、1つのダイアログに全メーターを
  縦に並べて表示する。各メーターの見出しは「一覧名: ラベル(またはフィールドラベル)」形式にし、
  複数の一覧が混在していても区別できるようにする。
- 単一一覧の「予算を確認」ボタン(`kintone.app.getQueryCondition()`を使う)とは集計の基準が異なる
  ("今表示している絞り込み" vs "一覧に保存された絞り込み")ことに注意。一括表示ボタンは複数の
  一覧を横断するため、個々の一覧を開かずに済む代わりに、ライブな絞り込み変更までは反映しない仕様とする。

### グループ制限の限界(重要、`related_record_summary`と同じ注意点)

`kintone.user.getGroups()`によるボタンの表示・非表示切り替えは、**クライアント側の表示ゲートに
過ぎず、真の権限制御ではない**。ボタンを非表示にしても、対象グループに属さないユーザーが直接
REST APIを呼び出せば同じ集計は可能である(このプラグインは読み取り専用の集計であり、レコードの
閲覧権限自体は変更しないため、実害は「本来見せたくない集計結果をUI上見せない」という範囲に限られる)。
この限界はsecurity-checklist.mdにも明記する。

## エッジケース

- 同じ一覧に複数の予算設定行がある場合、ダイアログ内に複数のメーターを縦に並べて表示する。
- 該当レコードが0件の場合は合計0円・0%のメーターを表示する(エラーにしない)。
- 一覧に紐づく予算設定はあるが、その一覧自体がアプリ設定側で削除された場合、`view-matcher.js`が
  単に一致しなくなるだけで、ボタンが表示されなくなる(エラー扱いにしない)。
- 集計対象フィールドがアプリ設定変更で削除された場合、レコード取得時に該当フィールドのプロパティが
  存在せず`undefined`になるが、`aggregator.js`の数値変換ガードで自動的に集計から除外され(=0扱い)、
  例外にはしない。
- レコード閲覧権限が無いユーザーがボタンを押した場合、REST取得が失敗するため、集計を中止し
  エラー内容をalertで表示する(ダイアログは開かない)。
- 一覧を切り替えるたびに`app.record.index.show`が再発火し、都度ボタンの要否を再判定する
  (前回描画したボタンは`kintone.app.getHeaderMenuSpaceElement()`の子要素からクラス名で毎回検索して
  取り除いてから、必要な場合のみ作り直す。「予算を確認」ボタンは一覧固有のため一覧を跨ぐたびに
  出たり消えたりするが、「すべての予算を確認」ボタンは対象一覧に関わらず条件(設定1件以上・
  許可グループ所属)が変わらない限り毎回表示され続ける)。
- モバイル版では本プラグインは何も表示しない(`manifest.json`の`mobile`セクションを持たない)。
- 「すべての予算を確認」で、ある行の対象一覧が運用環境の一覧設定(`GET /k/v1/app/views.json`)に
  見つからない場合(未デプロイ・一覧が削除された等)、その行はエラーにせずスキップし、
  ダイアログ末尾に「n件の設定は対象の一覧が見つからないため表示していません」と表示する。
- 許可グループコードが1つも設定されていない場合、「すべての予算を確認」ボタンは誰にも表示しない
  (「グループ制限の限界」参照。空 = 全員許可ではなく空 = 誰も許可しない)。

## TDD

`src/js/lib/`配下の純粋ロジックをJestでユニットテストする(`pnpm test`)。

- `aggregator.js`: `related_record_summary`から`sum()`のみ抽出して流用。
- `aggregatable-fields.js`: `related_record_summary`と同一ロジックを流用。
- `paged-fetch.js`: `related_record_summary`と同一ロジックを流用(コメントのみ本プラグイン向けに調整)。
- `config-store.js`: `kintone.plugin.app.getConfig()`/`setConfig()`のペイロードの読み書きと既定値。
- `row-validator.js`: 予算設定行のバリデーション(未選択・0以下の予算・しきい値の大小関係)。
- `view-matcher.js`: 予算設定行の配列と現在の`viewId`から、該当する行を文字列比較で抽出する。
- `meter.js`: 合計値・予算・警告/危険しきい値から、使用率(%)・進捗バーの幅(0-100にクランプ)・
  レベル(`ok`/`warning`/`danger`)を計算する純粋関数。
- `group-authorization.js`: `kintone.user.getGroups()`の戻り値と許可グループコード一覧から、
  「すべての予算を確認」ボタンを表示してよいかを判定する(許可グループコードが空なら常にfalse)。
- `view-filter-index.js`: `GET /k/v1/app/views.json`のレスポンス(`views.一覧名 = {id, filterCond, ...}`)
  から、`viewId(文字列) → filterCond(文字列、未設定時は空文字列)`のインデックスを作る純粋関数。

kintone依存のグルーコード(`desktop.js`, `config.js`)は、Puppeteerによる実環境テスト(CLAUDE.md項目6)で検証する。

- `src/e2e/config-screen.e2e.test.js`: 設定画面で一覧・フィールドの選択肢が実際に絞り込まれること、
  行の追加・削除ができることを検証する。
- `src/e2e/budget-check.e2e.test.js`: TEST_APP_ID_1に予算設定を保存した状態で一覧画面を開き、
  「予算を確認」ボタンが表示され、クリックするとメーターを含むダイアログが開くこと、対象外の一覧では
  ボタンが表示されないこと、許可グループに所属するユーザーには「すべての予算を確認」ボタンが表示され
  複数一覧分のメーターが1つのダイアログにまとまって表示されることを検証する(合計値は
  REST APIで独立に計算した期待値と突き合わせる。詳細は`.claude/skills/e2e-test/SKILL.md`の

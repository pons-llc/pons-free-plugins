# テンプレート挿入プラグイン(template_insert)

## 機能概要

文字列(複数行)またはリッチエディターフィールドに、あらかじめ設定した定型文(テンプレート)を
挿入するプラグイン。テンプレート本文には他フィールドの値を埋め込むプレースホルダーを書ける。
テンプレートは複数設定可能で、通常モードではヘッダーメニュースペースにドロップダウン(挿入する
テンプレートの選択)+挿入ボタンを設置する。ラジオボタン連動モードでは、フォーム上の特定の
ラジオボタンフィールドの現在の選択値によって挿入するテンプレートが自動的に決まるため、
ドロップダウンは表示せず挿入ボタンのみを設置する。サブテーブルの各行を1回ずつテンプレートに
展開し、連結してまとめて挿入する「サブテーブル繰り返し」型のテンプレートにも対応する。
PC・モバイルの両方に対応する。

## 挿入方式(確定・実機確認済みの制約に基づく設計判断)

`kintone.app.record.getFieldElement()`は、公式ドキュメントで**利用できる画面がレコード詳細画面
(PC)とレコード印刷画面のみ**と明記されており、レコード追加・編集画面では対象外(その画面で
実行した場合はnullになる)。本プラグインの用途である「追加・編集画面での値の書き込み」には
そもそも使えないため、textarea/リッチエディターのカーソル位置を取得してその場所に挿入する、
という実装は行わない。

代わりに、`kintone.app.record.get()`で現在のフィールド値(文字列)を取得し、末尾に区切り文字を
挟んでテンプレート文字列を追記した新しい値を`kintone.app.record.set()`で書き戻す「末尾追記」方式
にする(「挿入」という機能名だが実体は追記)。区切り文字は、文字列(複数行)フィールドは改行
(`\n`)、リッチエディターフィールドは`<br>`。既存値が空の場合は区切り文字を挟まずそのまま
テンプレート文字列を設定する。

## プレースホルダー記法

テンプレート本文中に`{フィールドコード}`と書くと、挿入時にそのフィールドの現在値へ置換される。
対応するのはレコード直下の値を持つフィールド(文字列/数値/選択肢系/日付時刻/リンク/計算/
ユーザーその他エンティティ系)。値を持たないフィールド(ラベル・スペース・罫線・グループ・
関連レコード一覧)や、挿入先フィールド自身は候補に出さない(自己参照防止)。存在しない
フィールドコードを指定した場合、置換されずに`{フィールドコード}`のまま残る(気付けるように、
サイレントに消さない)。

- チェックボックス・複数選択・作業者: 値(配列)を「、」で連結
- ユーザー選択・組織選択・グループ選択・作成者・更新者: 表示名を「、」で連結(複数選択時)
- 添付ファイル: ファイル名を「、」で連結
- 日付・時刻・日時・作成日時・更新日時: kintoneの生のvalue文字列をそのまま使う(タイムゾーン
  変換や表示形式の整形は行わない。将来的な要望があれば別途対応)
- 上記以外(文字列1行/複数行・数値・リンク・計算・ラジオボタン・ドロップダウン・レコード番号):
  valueをそのまま文字列として使う

**リッチエディターへ挿入する場合、置換される値は必ずHTMLエスケープする**(セキュアコーディング
ガイドライン対応。フィールドの値に`<script>`等が含まれていても、リッチエディターとしてそのまま
描画されないようにするため。テンプレート本文自体はプラグイン管理者が入力する信頼できる文字列
として扱うが、挿入時に埋め込まれる値はレコードの実データであり、他ユーザーが入力した可能性がある
ため必ずエスケープする)。テンプレート本文中の改行は、挿入先が文字列(複数行)ならそのまま
(`\n`)、リッチエディターなら`<br>`に変換する。

## サブテーブル繰り返し型テンプレート

テンプレートごとに、通常型か「サブテーブル繰り返し型」かを選べる。繰り返し型では対象サブテーブル
(フィールドコード)を指定し、本文中のプレースホルダーにはレコード直下のフィールドコードに加えて
その対象サブテーブル内の列コードも使える(サブテーブル内の列コードはアプリ全体でユニークなため、
レコード直下のフィールドと衝突しない)。挿入時、対象サブテーブルの行ごとに本文を1回ずつ展開し、
行区切り(挿入先が文字列複数行なら`\n`、リッチエディターなら`<br>`)で連結した結果をまとめて
1回で末尾に追記する。行が0件の場合は追記対象の文字列が空になるため、挿入ボタン押下時に
「対象のテーブルに行がありません」と案内し、追記自体を行わない。

## UIモード(プラグイン単位で1つ選択)

### 通常モード(ドロップダウン)

`kintone.app.record.getHeaderMenuSpaceElement()`(モバイルは`kintone.mobile.app.getHeaderSpaceElement()`)
に、テンプレート名の一覧を並べた`<select>`と「挿入」ボタンを設置する。ボタン押下時、選択中の
テンプレートを解決・挿入する。

### ラジオボタン連動モード

設定で指定したラジオボタンフィールドの選択肢ごとに、挿入するテンプレートを1つ対応付ける
(対応するテンプレートが無い選択肢もあってよい)。ヘッダーにはドロップダウンを出さず「挿入」
ボタンのみを設置する。ボタン押下時、その時点のラジオボタンの値に対応するテンプレートが無ければ
「現在の選択肢に対応するテンプレートがありません」と案内し、何もしない。ラジオボタンの値が
変わるたびにボタンの有効/無効を切り替える(`app.record.create.change.<code>` /
`app.record.edit.change.<code>`を監視。ヘッダーのボタン設置・クリック処理自体は
`kintone.events.on()`のハンドラーの外側の通常の`addEventListener('click', ...)`なので、
`record.get()`/`record.set()`の呼び出し制限を受けない。org_lookup/self_lookupと同じ理由)。

## 設定画面

- **表示モード**: 通常モード(ドロップダウン) / ラジオボタン連動モード
- (ラジオボタン連動モードのみ)**連動するラジオボタンフィールド**: フォーム上のラジオボタン
  フィールドから選択
- **テンプレート一覧**(複数行、追加/削除可): 各テンプレートにつき
  - テンプレート名
  - 挿入先フィールド(文字列複数行・リッチエディターのみ選択可)
  - 種別: 通常 / サブテーブル繰り返し
    - サブテーブル繰り返しの場合: 対象サブテーブル(フィールドコード)
  - 本文(複数行テキスト。プレースホルダー一覧をクリックで本文へ挿入できる補助UIを設ける)
  - (ラジオボタン連動モードのみ)対応するラジオボタンの選択肢(未選択でもよい=そのテンプレートは
    ラジオ経由では使われない)

## エッジケース

- 対象フィールド(文字列複数行・リッチエディター)がアプリに1つも無い場合、設定画面に警告を表示し
  テンプレートを追加できないようにする。
- ラジオボタン連動モードで、フォームにラジオボタンフィールドが1つも無い場合、モード自体を選択
  できないようにする。
- テンプレートが1件も無い状態でヘッダーの挿入UIを設置しようとした場合、何も設置しない(空の
  ドロップダウン・無意味な挿入ボタンを出さない)。
- 挿入先フィールドが`disabled`(他プラグイン等により無効化)の場合でも、値の書き込み自体は
  `record.set()`のレベルで可能(kintone公式仕様。表示上グレーアウトされるだけで無効エラーには
  ならない)ため、特別扱いはしない。

## モバイル対応

`kintone.mobile.app.getHeaderSpaceElement()`は`kintone.app.record.getHeaderMenuSpaceElement()`
と異なり`app.record`ではなく`app`直下のAPIであることに注意(実機確認済み、公式ドキュメント
「ヘッダーの下側の要素を取得する」)。UI・ロジックはPC版と同じ(ドロップダウン+挿入ボタン、
または挿入ボタンのみ)。`kintone.mobile.app.record.get()`/`set()`はPC版と同じ形式のレコード
オブジェクトを扱う。

## アーキテクチャ(TDD対象は`js/lib/`)

```
js/lib/config-store.js            … kintone.plugin.app.getConfig/setConfig()の読み書き、デフォルト値
js/lib/config-validation.js       … 保存前バリデーション(表示モード別の必須項目、テンプレートの
                                     挿入先フィールド種別チェック等)
js/lib/field-value-formatter.js   … フィールド型ごとにプレースホルダー用の文字列へ整形する純粋関数
js/lib/placeholder-resolver.js    … テンプレート本文+値マップからプレースホルダーを解決する純粋関数
                                     (通常型・エスケープ・改行変換を含む)
js/lib/subtable-template.js       … サブテーブル繰り返し型テンプレートの展開・連結(purelaceholder-resolverを
                                     行ごとに呼び出して連結する純粋関数)
js/lib/insert-composer.js         … 既存フィールド値+挿入テキストから、追記後の新しい値を組み立てる
                                     純粋関数(区切り文字の付与)
js/lib/radio-template-mapping.js  … ラジオボタンの現在値からテンプレートを解決する純粋関数
js/desktop.js / js/mobile.js      … 上記libを組み合わせ、ヘッダーへのUI設置とイベント配線を行う
                                     (kintone依存、ユニットテスト対象外)
js/config.js                      … 設定画面のUI(kintone依存、ユニットテスト対象外)
```

## kintoneドキュメントMCPで確認済みのAPI仕様

- `kintone.app.record.getHeaderMenuSpaceElement()`(PC専用。利用できる画面: 詳細/追加/編集画面)
- `kintone.mobile.app.getHeaderSpaceElement()`(モバイル専用。`app`直下のAPIで`app.record`配下
  ではない。利用できる画面: 一覧/詳細/追加/編集画面)
- `kintone.app.record.getFieldElement()`は追加・編集画面では利用不可(利用できる画面が詳細画面・
  印刷画面のみと明記されている)。上記「挿入方式」の設計判断の根拠。
- フィールド形式(`/ja/kintone/docs/overview/field-types/`)で、文字列複数行(`MULTI_LINE_TEXT`)は
  `\n`区切りの生文字列、リッチエディター(`RICH_TEXT`)はHTML文字列であることを確認。テーブル
  (`SUBTABLE`)の行オブジェクト形式(`{id, value: {列コード: {type, value}}}`)も確認済み。
